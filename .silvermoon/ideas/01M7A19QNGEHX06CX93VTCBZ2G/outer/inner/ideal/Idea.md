# Task 输入与结果的类型化内容引用

## 问题

当前 Task 将 JSON result 与可写文件树 output 分开表达，核心运行事实及引用资源也分别保存在数据库与内容存储中。组合、保留、导出和恢复缺少统一的完整性边界。

## 结果

让 parameters/message/result 通过自带 cidPaths 的载荷表达强引用，以 RunHistory 为单位保存执行与交付 DAG，Task 为请求/关联/投影，SQLite 主要作为可重建索引。以受控 CID 访问替代 Worker Space，并通过受管理根保护依赖闭包；已确认方向见[讨论记录](Discussion.md)，严重未决项见[待决定项](OpenQuestions.md)。

## 边界

- 正式 Payload 的 CID 是强依赖，缺失或无法验证的闭包不能成功接纳或交付；引用与普通数据无歧义，不附加 path，Task 不解释文档内部语义。
- 核心事实以不可变 DAG 版本存储，pin 不代替事务或权限；保留共享 Run、顺序、幂等及不确定恢复语义，权威根与历史策略须先确认。
- 文件资源首期 raw/UnixFS，结构化记录另有 DAG 编码；直接替换现有内部协议且不迭代已有 Schema/API 版本，不重写历史制品、不自动公开私有事实。

## 验收标准

- 三通道及父子引用在 JSON、逻辑值和 DAG 间往返，闭包完整；普通字符串、同形对象及判别分支中的普通数据不误转换。
- 从权威根及 DAG 重建查询索引后，Task/Run、消息、幂等与恢复语义一致；提交、pin 与清理失败不会产生半提交或重复副作用。
- Worker 无需 Space 即可流式读取/解析/存储内容，按根保留不破坏共享执行；只读树形包按需引入，旧交换协议完整替换且已有版本号不递增。
