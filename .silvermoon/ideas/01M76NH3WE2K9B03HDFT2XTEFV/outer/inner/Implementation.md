# 实施初版

## Steps

### I-S01: 统一引用调用与执行身份

将 SDK 子调用入口统一为 bundle SpaceRef，跨 Worker 传输协议引用，由 Engine 有界解析目标目录并持久化来源与目标 CID。保持调用 key 的幂等意图和固定身份；先检查来源策略，避免未授权引用触发完整下载。静态视图创建不承诺内容已经获取，首版拒绝可写空间。

### I-S02: 明确构建与准备闭包

基于已有 resources 子树组合能力完善静态依赖的构建表达和准备契约，以真实 DAG 链接而非不透明归档引用子 bundle。保持子 bundle 根 CID，按 CID 去重，定义闭包容量与运行期间内容保留；外部静态引用单独准备并授权。

build 负责获取并交付自包含 task folder，car 保持离线。提取 Builder 与 Engine 共用的内容获取、验证和块缓存能力，不耦合 Engine 生命周期；两者默认读取独立公共内容配置并允许分别覆盖网关和 data dir。共享目录需保持并发写入与运行期保留安全，不混入 Engine 运行数据库。

### I-S03: 更新验证与作者文档

覆盖嵌套与共享依赖、离线准备、固定身份、动态引用和拒绝路径，更新 SDK、构建器与 Engine 的相关文档和示例。不引入循环 Merkle 依赖，也不把子调用合并为父 Run。

## Acceptance criteria

### I-AC01: 单一入口与固定身份

通过类型检查及集成测试证明父 bundle 子树和 context.space(cid).root 使用同一入口，旧 CID 与路径双参数被拒绝；持久化与重试使用已固定的目标 CID。

### I-AC02: 完整且有界的静态闭包

以包含共享孙任务的组合测试证明依赖根 CID 保持不变、唯一块去重和准备后断源执行成功；缺块、容量耗尽均有明确失败证据。证明 build 后的完整目录无需机器缓存或网络即可生成 CAR，并覆盖公共默认配置、独立覆盖和共享目录的并发与保留边界。

### I-AC03: 权限与执行隔离不退化

通过未授权来源、可写空间引用及子任务生命周期回归测试证明默认边界、取消、预算和独立身份保留，并运行 pnpm check。
