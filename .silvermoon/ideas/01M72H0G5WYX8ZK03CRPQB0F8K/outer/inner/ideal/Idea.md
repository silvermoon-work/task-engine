# Task Builder CLI Redesign

## 问题

Task 生产者需要清晰、稳定的项目创建、模块构建与 CAR 交付接口，避免输入来源、输出位置及失败后的产物状态含糊不清。

## 结果

以 `init`、`build`、`car` 覆盖三个生产场景，让开发者、AI 代理与 CI 使用同一份可观察契约。
完整用户期望契约见本目录的 [CLI Spec（定稿 r14）](./task-builder-cli-spec.html)，不是代码实现架构或已执行证据。

## 边界

1. 仅提供三个业务命令；运行、托管、上传、认证与发布不在范围内，依赖安装由外部工具承担。
2. `build` 只覆盖本次同名产物，不递归清空目录；`init` 和独立 `car` 拒绝覆盖，输入不被修改。
3. 构建面向可信项目，自动求值 JS/TS 契约并拒绝求值期间的输出尝试；不是沙箱，不限制 Task 运行时日志。

## 验收标准

1. 三个场景的参数、版本固定规则、默认路径与交付物可按 Spec 逐项核对；构建业务内容不能由 CLI 覆盖。
2. 成功、失败、部分交付与取消均有明确的单对象结果及退出码，TTY 与非 TTY 一致；旧 CAR 不被冒充为本次结果。
3. Spec 的十个示例完整展示预期输入输出，并与命令章节、共享契约及锚点一致；示例和设计验证不代表 CLI 已实现或运行成功。
