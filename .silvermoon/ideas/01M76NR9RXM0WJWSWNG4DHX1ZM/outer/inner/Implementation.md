# Implementation

## Steps

### I-S01: 验证模块加载兼容性

依据已确认的至少 Node 22.15 方向，验证同步 hook 与 CJS 入口组合并确定支持下限，检查完整 CJS API；设计本仓库维护的新版本 schema、产物加载契约及执行前旧产物拒绝机制，不用 Node 版本推断产物兼容性。

### I-S02: 接入受控 IPFS 模块加载

使用随包分发的 Worker bootstrap 接入只读已验证入口映射的模块适配，不在 hook 中联网。同步调整 Builder 地址生成、Protocol/SDK 加载契约、受影响的 Node 声明和模板，保持任务生命周期及单文件交付形态。

### I-S03: 补齐回归验证与使用说明

覆盖新产物加载、双向版本拒绝、CJS 行为、地址语义和生命周期，更新 CI、迁移与使用说明；验证新 schema 的分发入口与实际校验一致，不依赖外部仓库更新。

## Acceptance criteria

### I-AC01: IPFS 入口保持任务行为

集成测试证明重建的 CJS bundle 可由 IPFS 入口运行，import.meta.url 正确，任务输入、结果、消息、日志和退出行为不退化；同一入口不重复求值且不同 Run 状态隔离。

### I-AC02: 读取与授权失败可观察

针对旧产物、无效 CID、路径越界、非入口路径、跨 CID、内容校验失败、容量超限与取消的测试证明明确失败；旧产物拒绝测试证明作者代码尚未执行，新 schema 与产物校验一致，旧引擎明确拒绝新产物，且无静默 eval、源码改写或临时文件回退。

### I-AC03: 运行时及隔离边界成立

在确定的最低 Node 版本及支持版本验证 require.cache、require.resolve 与内置模块；回归测试证明 bootstrap 先于入口生效、宿主加载器未改变、关闭和并发执行不串用权限。直接受影响的声明、模板和 CI 与实际下限一致。
