# CLI Redesign：围绕生产者与执行者重设计命令体验

## 问题

现有 CLI 的命令边界与内部流水线混杂，用户级参数和应用资产需求尚未系统发现。
这使必要输入、默认值与辅助能力的范围难以一致判断。

## 结果

以生产者和执行者各自的主任务为中心，依据
[Builder 需求分析](./task-builder-requirements.md)和
[Engine 需求分析](./task-engine-requirements.md)，形成精简、可解释且兼容自动化的 CLI。

## 边界

- 按 CLI 外部用户参与分段：Builder 初始化后由用户编辑，再构建；CAR 是构建目标，
  消费端验证归入 Engine `run --dry-run`，不新增独立验证任务。
- 区分 Config、Credential 与 App 资产；候选配置、历史与认证功能不视为已批准范围。
- 保留 JSON 默认、执行安全和消费端无编译器边界；TUI 仅为可选交互，不自动发布。

## 验收标准

1. 两个 CLI 的主任务、分段与参数均有明确依据；构建自带验证，预演校验 Bundle、输入和
   配置，但不执行任务代码、不伪造真实执行结果。
2. 用户级值的来源可解释，普通配置与凭证访问隔离，资产所有权与管理范围明确。
3. 旧调用有明确兼容路径，默认机器输出稳定，执行完成与资源回收的真实语义不退化。
