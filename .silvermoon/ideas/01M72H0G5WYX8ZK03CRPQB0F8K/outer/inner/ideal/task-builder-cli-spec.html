需求依据

1. 用户与边界

R1：Task 生产者。人类开发者、AI 代理和 CI 是交互上下文，不是不同业务角色。负责生产与交付，不负责执行、运行历史、HTTP 服务、内容托管、上传、pin、认证或发布。编辑与依赖安装由外部工具承担。

2. 主场景清单

主场景与用户参与
场景目标与完成标准外部参与
S1 创建项目得到完整可编辑新项目；不安装、不覆盖。用户编辑源码/契约/资源并按需安装依赖后，可进入 S2。
S2 构建交付读取 task.build.yaml，默认生成有效模块与 CAR；可关闭 CAR，重复构建默认覆盖同名产物。已有项目直接使用，不要求先经过 S1；完成后由外部系统执行或分发。
S3 已有 Task 打 CAR输入 task.yaml，按声明匹配文件，交付有效 CAR 与 CID；不重新 build。已有模块可来自其他构建过程；不要求调用过 S1/S2。

3. 分场景输入与固定规则

输入范围
场景输入与选择边界
S1项目位置、包名、初始 Task 名称模板生成完整可编辑项目；生成后由项目文件决定后续构建。本章已确认。
S2构建描述、可明确指定的模块输出目录、是否关闭 CAR不覆盖声明中的任务业务内容；默认交付模块与固定名称的 CAR，--no-car 仅关闭本次 CAR。本章已确认。
S3已有 task.yaml，以及本次 CAR 输出位置按声明匹配文件，不把目录里的所有内容打包；不重新 build。本章已确认。

CLI 与 Builder 依赖使用当前实际运行的各自版本，SDK 使用当前 Builder 发行配套版本；三者不要求同号，不允许指定其他版本，也不查询远端 latest/canary 替代。构建面向可信作者项目，按需执行 JS/TS 契约，不另设授权开关或提示；契约及其求值期间执行的依赖禁止日志和标准流输出。

固定约束：构建业务内容不可覆盖，模块输出目录可本次指定；生成 CAR 后保留模块；失败不报成功、不修改输入。build 允许覆盖同名产物，init 与独立 car 命令保留各自的拒绝覆盖规则。业务结果默认 JSON。构建不是沙箱，只应构建可信作者项目；容量与遍历预算为内部约束。

4. 支撑资源

项目输入、已安装依赖、模块与 CAR 为用户或包管理器所有，不作为 Builder 托管资产。Builder 只拥有本次临时输出与编码暂存，完成/失败/取消后释放；不引入缓存、隐藏产物副本、历史数据库或常驻服务。

5. 辅助场景边界

现有需求不需要额外的独立辅助管理场景；项目文件由作者维护，本次输出要求由调用决定。

输出流、帮助与退出码

  • 业务成功：stdout 恰好一个 {ok:true,data:…} JSON 对象并以换行结束；data 内容由命令章节定义。不混入进度、横幅或警告。示例为了阅读展开 JSON，不规定序列化缩进。
  • 业务失败：stdout 恰好一个 {ok:false,error:{code,message}} JSON 对象并以换行结束；没有可信结果时省略 data。若已获得可信的部分交付物，同一对象保留 data 与 error，例如有效模块已完成但 CAR 失败。data 只表达实际已知结果，不伪造成功，不输出多个结果对象。
  • error 必须且仅包含非空字符串 code 与 message，不另设 hint 或 details。code 标识错误类别；message 说明具体问题，仅在确有可用建议时补充恢复提示；不要求每个错误都附建议，不输出秘密或任意输入全文。
  • stderr 仅用于 CLI 实现自身的 logging，默认空，不属于结果契约；不能独占承载错误原因或任何必读结果。契约代码的日志不得转发至任何标准流，违规按标准 JSON 错误报告。不输出常规进度。--help 以及根命令 --version 例外：stdout 为文本，退出 0；只显示帮助/版本时不读业务文件、不执行代码。
  • exit 0 成功/帮助/版本；1 所有普通失败，包括用法/选项/类型、业务、文件、校验错误。130 用于 SIGINT，143 用于 SIGTERM，且仅在本次操作结果与资源清理均已确认时使用。若变更、写入或资源释放状态无法核实，必须返回 1 并通过 error.code/message 说明不确定性，不能用中断掩盖未知结果。工具能够处理的取消也向 stdout 输出一个 ok:false 的 JSON 对象；可信部分交付物放 data。143 为本 CLI 明确保留的扩展值。
  • 未知或重复选项返回 1；不提供 --format、不提供 --quiet/--verbose、不提供通过 stdin 传源码/声明/归档的模式；不提供隐式交互向导。
  • TTY 与非 TTY 行为一致；不弹确认，不因终端类型改变结果结构。build 默认覆盖本次同名产物，不提供额外覆盖开关；init 和独立 car 命令仍拒绝覆盖既有目标。覆盖输出不能扩大为删除输入或递归清空任意目录。

值的来源与路径

  • init：项目包名和 Task 名称由本次明确值或项目身份推导；其他内容由模板生成，生成后由作者编辑项目文件。
  • build：源码/契约/身份/运行/资源规则只读 task.build.yaml。模块位置：--out-dir > 文件 outDirectory > 构建描述所在目录下的 dist。不会重写构建描述。
  • build 默认交付模块与 CAR；--no-car 只关闭本次 CAR 生成，不接收路径或其他值。模块始终保留。CAR 名称与位置由模块输出目录确定，不提供单独覆盖入口。
  • build 的 CAR 固定为模块目录父目录中的“模块目录 basename.car”。修改模块输出目录后按新模块位置推导 CAR。独立 car 命令的默认位置采用同一规则，但仍保留已确认的 --output 选项。S3 的模块目录为 task.yaml 所在目录；默认名称无法推导时，build 拒绝该模块输出位置，S3 要求显式输出文件。
  • 命令行相对路径以 cwd 为基准；构建描述里的相对路径及缺省 dist 均以构建描述所在目录为基准；模块声明里的相对路径以声明所在目录为基准。输出 JSON 使用宿主绝对路径，模块内相对文件名使用协议的 /。
  • 模块输出不能包含构建输入或被资源匹配遍历；CAR 输出不得位于输入模块目录内、等于构建描述或任何构建输入，不得经链接或路径逃逸触碰范围外文件。build 可替换本次确定的同名产物，不递归清空输出目录；未选入本次声明的旧文件不参与模块验证或 CAR 封装。独立 car 命令仍拒绝覆盖目标。

示例与安全

所有示例都是预期契约，不是运行证据；不会在打开文档时执行。示例 CID 展示合法身份字符串的形式，不代表这些示例文件字节实际计算出的值；实际工具必须计算并校验真实 CID。示例路径假设工作目录为 D:\\work\\demo，init 示例单独假设 cwd 为 D:\\work。示例模块是包含最小声明/Worker/三份 Schema 的有效模块，未选择附加资源。

面向作者的工具将 build 视为运行可信项目的构建流程。JS/TS 契约会按需执行宿主代码，并非沙箱；只读模块声明及 JSON 契约不触发此执行，S3 也不执行代码。契约及其求值期间执行的依赖禁止 console 的日志输出以及直接写 stdout/stderr；检测到输出尝试即以 CONTRACT_OUTPUT_FORBIDDEN 失败，不转发日志、不静默丢弃后报成功。此规则针对构建时的契约求值，不限制 Task 在 Engine 中执行时的日志。普通参数校验必须在启动写入/代码求值前尽量完成；允许覆盖不等于允许截断输入或因目标竞争而覆盖错误位置。

接口边界

本 Spec 只定义命令树中的新接口，不设计额外别名或旧语法兼容层；实际版本切换与迁移安排不属于本次文档范围。根命令仅为分组，无参显示帮助并退出 0；--help 在任意层级显示对应帮助；根命令 --version 显示当前 CLI 版本。不另设可调用 help 子命令。文档定稿不授权修改实现、删除现有功能或发布。

返回命令树

task-builder init

已批准 · 关联场景 S1 · 本章独立审批，需求批准不等于接口批准。

创建可编辑的新 Task 项目，不安装依赖、不构建、不合并或覆盖既有项目。

task-builder init <directory> [--package-name <name>] [--task-name <name>]
task-builder init --help

适用全部共享契约，特别是输出/退出码与值来源/路径。本章明列的帮助文本与阶段性保留是特定行为，无其他隐含例外。

参数

参数、默认与约束
名称类型与渠道必需性初值/回退约束与冲突
<directory>位置参数 · path必填无父目录须已存在；目标不得存在；不通过 stdin 读取
--package-name <name>string · npm 包名可省略目标目录 basename写入 package.json 的 name 字段；若目录名不是有效包名则要求明确提供本选项，不静默改写名称
--task-name <name>string · Task 名称可省略本次项目包名的非 scope 部分由本次项目身份推导；非空，符合 Task 协议

stderr

退出码
0 成功/帮助；1 参数、选项、生成、兼容性、路径或写入失败，包括状态或清理不确定；130/143 仅用于结果和清理均已确认的取消。
文件与资源
只创建新项目；所有生成路径和引用一致。CLI、Builder 依赖固定为当前实际运行的各自版本，SDK 固定为当前 Builder 发行配套版本；三者不要求同号，不允许选择其他版本。元数据无效时明确失败，不查询远端替代。失败时清理本次未完成项目，不碰既有目标或父级项目。
交互
缺少 directory 返回参数错误，不进入向导。TTY 与非 TTY 均不提问、不读 stdin；--help 按共享规则。

设计说明

  • 初始化只接收本次项目身份。模板提供完整可编辑的构建描述、源码、JSON 契约及示例资源，不要求创建时逐项选择构建设置。
  • 模板初值：源码 src/main.ts、契约 src/contract.json、explicit 入口、Node 最低版本 22.13.0、资源 assets/** 映射至 resources/、二进制规则为空、模块输出 dist。初值是项目交付内容，不是额外的 CLI 参数。
  • 生成后由作者编辑项目文件决定构建语义，包括改用 callback 或代码契约；后续 build 不重新注入模板初值。

返回命令树 · 共享契约

task-builder build

已批准 · 关联场景 S2 · 默认覆盖与 CAR、契约无日志、默认路径及相关交付边界。

读取构建描述，默认生成完整有效的 Task 模块及固定名称的 CAR；重复构建覆盖同名产物，可关闭本次 CAR 生成。

task-builder build [build-file] [--out-dir <directory>] [--no-car]
task-builder build --help

适用全部共享契约，特别是输出/退出码与值来源/路径。本章明列的帮助文本与阶段性保留是特定行为，无其他隐含例外。

参数

参数、默认与约束
名称类型与渠道必需性初值/回退约束与冲突
[build-file]位置参数 · path语义必需，可省略路径.\task.build.yaml读取本次项目声明；相对源码/契约/资源路径以构建描述所在目录为基准；不另设 --root
--out-dir <directory>path可省略优先构建描述 outDirectory；未声明时为构建描述所在目录下的 dist本次明确值优先；命令行相对路径以 cwd 为基准；项目值和缺省 dist 以构建描述目录为基准
--no-carboolean 开关可省略未传则生成固定名称 CAR传入只关闭本次 CAR，不接收路径或值，不删除旧 CAR；没有单独指定 build CAR 名称或位置的选项

预期输出与交互

stdout
成功：一个 {ok:true,data} JSON 对象。data.module.directory 为模块绝对路径；data.module.declaration 为生成声明绝对路径；data.module.files 为本次声明选中的完整模块相对文件列表，不包括未选入的遗留文件；data.cid 为本次有效模块的身份；data.car 默认是 {path}，--no-car 时为 null。data.car:null 仅表示本次没有交付 CAR，不表示目标位置不存在旧文件。失败：一个 {ok:false,error:{code,message}} 对象；若新模块已有效完成但 CAR 失败，同一对象保留可信 data.module、data.cid 及 data.car:null；message 说明旧 CAR 是否仍保留或状态不确定，不将其冒充为本次结果。
stderr
仅 CLI 实现自身日志，默认空；契约日志禁止转发。CAR 失败、保留模块及清理结果必须在 stdout 的最终对象中完整表达。
退出码
0 成功/帮助；1 参数、冲突、契约输出违规、构建、校验或交付错误，包括状态或清理不确定；130/143 仅用于结果和清理均已确认的取消。
文件与资源
默认交付模块与 CAR，并覆盖对应同名产物，不需要覆盖开关。覆盖仅针对本次生成文件，不递归清空模块目录；未选入新声明的旧文件不打入 CAR。先完成构建和内容验证，再更新输出；此前失败不修改旧输出。替换单个目标须交付完整内容，不先截断旧文件；模块只有整体有效时才可作为可信 data 返回。交付阶段异常须明确已完成的部分与不确定状态，不能声称未验证的回滚成功。模块更新完成后 CAR 失败时保留新模块，并保留尚未成功替换的旧 CAR，清理本次临时输出。--no-car 不更新也不删除已有 CAR。
交互
面向作者的可信项目：执行 build 本身即触发必要的 JS/TS 契约求值，不另设授权开关或提示；JSON 契约只解析数据。求值期间输出日志或直接写标准流会导致构建失败。构建不是安全沙箱，不应对不可信项目执行。不提供 name/runtime/source/include/binary 的覆盖选项；没有 --format、预算选项或 stdin 入口。TTY 与非 TTY 均无提示；取消遵循相同的阶段性保留规则。

设计说明

task-builder car

已批准 · 关联场景 S3 · 本章独立审批，需求批准不等于接口批准。

以已有 task.yaml 为入口，按声明选择文件，封装成有效 CAR；不执行构建。

task-builder car <task-file> [--output <file>]
task-builder car --help

适用全部共享契约，特别是输出/退出码与值来源/路径。本章明列的帮助文本与阶段性保留是特定行为，无其他隐含例外。

参数

参数、默认与约束
名称类型与渠道必需性初值/回退约束与冲突
<task-file>位置参数 · path必填无指向已有 task.yaml 文件，不接受目录；按协议校验声明；不将整个目录归档
--output <file>path可省略声明目录的父目录下，以模块目录名生成 .car 文件名显式位置优先；相对路径以 cwd 为基准；不得覆盖既有文件，不得位于输入模块目录内

预期输出与交互

stdout
成功：一个 {ok:true,data} JSON 对象，data.car 为 CAR 绝对路径；data.cid 为实际交付归档的根身份；data.declaration 为输入声明绝对路径；data.files 为按声明选入归档的完整相对文件列表。失败：返回一个 {ok:false,error:{code,message}} 对象，没有可信交付物时省略 data。
stderr
仅实现自身日志，默认空；不能独占承载错误原因或其他必读结果，不输出常规进度。
退出码
0 成功/帮助；1 参数、目录代替文件、输入、验证、路径或写入错误，包括状态或清理不确定；130/143 仅用于结果和清理均已确认的取消。
文件与资源
只写新 CAR 文件及本次临时输出，不改输入。相对路径以声明文件所在目录为基准；声明本身入包；不读取未选中文件的内容。
交互
不读 task.build.yaml、不编译、不执行代码契约、不安装依赖、不访问网络。TTY 与非 TTY 均不提问；不提供目录递归全打包、独立 CID 文件、stdin 归档流模式。
