# 待决定项：类型化内容引用

本文件支持 [Idea](Idea.md)。2026-11-14 的强引用与 DAG 事实源要求使此前“主要决策已全部收敛”失效。当前严重取舍列在下方 R-01 至 R-04；证据、失败例子和建议见[架构评估](../ArchitectureReview.md)，依赖与退出门槛见[分阶段计划](../RefactorPlan.md)。局部设计确认不是完整构想验收。

## 当前需要讨论的严重取舍

### R-01: 谁权威地记录当前根与提交结果

pin 集合不能区分正式提交、候选与旧版本。建议保留 Store 小型耐久 head/intent registry，可继续使用独立 SQLite；任务查询 SQLite 可删重建，但协调数据库属于备份范围。

需确认“SQLite 主要作为索引”是否允许这一协调元数据例外。若全部 SQLite 都可丢弃，就必须另外保留独立耐久根日志/锚点，不能通过扫描块猜测当前状态。

### R-02: Run 前/全域事实与历史保留

用户已纠正记录单位为 RunHistory，Task 是请求/关联/投影，共享执行的模型歧义已解决，无需再确认。建议以受管理根集合覆盖 RunHistory、独立交付及尚无 Run 的申请/全域恢复事实。

剩余需确认：允许 Run 前申请、跨 Run 准入/幂等事实有独立耐久根；关闭的 RunHistory 按当前保留策略整份回收，而非永久审计。Run 保留期内必要历史不断链，但域级旧根不能让过期 Run 永久可达。

### R-03: 不完整入站申请如何耐久保存

强 Payload 接纳前必须完整，但准备中的请求可能尚缺依赖。建议允许不可执行的 AdmissionAttempt 保存受限原始请求字节/描述符，闭包验证成功后才生成正式强 Payload；不完整结果只生成不链接缺失节点的失败事实。

需确认这一草稿/正式载荷分层，或明确改变现有 durable preparing 行为。它不是给已接纳 Payload 保留弱引用兼容模式。

### R-04: 核心 DAG 的私有存储边界

RunHistory 根会可达参数、消息和执行事实，Engine 授权不会自动保护另一个可读块的网关/Kubo 入口。建议首期默认私有受控 Store，不自动公开核心根；公共资源或交付导出独立授权。

需确认部署边界能提供私有性。若要求公共/不可信网络承载核心数据，须另定加密、密钥与导出策略，不能当作一般文件读取的细节。

## 先前讨论项的当前状态

## B-01: 传输载荷与引用定位元数据

已确定自带 cidPaths、类型与判别分支推导、通配符优先。新增强链接 DAG 编码；采用受限 JSONPath AST、引用位置集合校验与复杂情况具体位置回退，细节和测试见架构评估 D-01/D-02。不重新讨论已确认命名。

## B-02: 引用对象与受控内容能力

已有决定继续有效：ContentRef 只表示身份，context 提供 CID 读取/解析/临时存储；资源 file/directory DU 支持 raw/UnixFS 流。新增结构化 DAG 记录走宿主明确的块/codec 接口，不伪装成第三种文件节点。ipfs-access 拥有共享访问契约，ipfs-tree 按需引入。

## B-03: 强闭包与根保留

弱引用策略已被强引用取代，缺失依赖不允许正式接纳或成功交付。运行暂存、发布前闭包验证、多 owner 与先保留后释放继续有效；如何权威提交根、覆盖共享 Run 和回收历史上升为 R-01/R-02。

## B-04: 协议调整的覆盖范围

全部切换与不迭代已有 Schema/API 版本继续有效。新增范围包括 RunHistory/Delivery/消息及必要请求/恢复事实 DAG 化和查询 SQLite 重建，不建立 TaskHistory；不能只搬迁 input/result 字段而遗漏幂等、准入下界和资源释放证据。保持现有调度语义，实施计划将底层提交证明放在公开协议切换之前。
