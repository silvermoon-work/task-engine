# Task Engine CLI 需求分析报告

本文是 [CLI Redesign Idea](./Idea.md) 的理想世界支持文档，不代表功能已经实现。
现状基线为 `a635ed0`；“建议”是重设计方向，“待定”需要后续决策，不是现有产品承诺。
参数发现覆盖完整执行上下文，不以当前是否暴露 flag 或是否已有持久化作为唯一判断依据。

## 1. 用户是谁？

主要用户是 Task 的执行者：消费一个既有 Bundle，提供业务输入并获得执行结果。
终端用户、AI 代理与 CI 都可以承担该角色；它们的呈现方式不同，业务职责相同。

Engine CLI 不负责创作、编译、修复或发布 Bundle，也不默认成为常驻 HTTP 服务、
内容节点管理员或远端调度平台。执行的是用户信任的代码，校验和子调用授权不等于沙箱。

## 2. 主需求、主任务是什么？

**主需求：执行指定 Task，并获得可信的业务结果与执行结论。**

一次执行接收 Bundle 身份/来源和业务输入，自动进行校验、内容准备、准入、运行、结构化
子调用、完整耗尽与清理。它们是一个主任务的内部过程，不应因为内部阶段不同而增加多个
必须依次调用的命令。

| 主任务模式 | 分段依据 | 完成标准 |
| --- | --- | --- |
| 执行 Task | 正常情形无必需的 CLI 外部用户参与，单次调用完成 | 交付明确成功或失败结果；成功必须包括工作耗尽、资源清理确认 |
| 执行预演 `run --dry-run` | 同一执行任务的显式模式，不新增独立 check 任务，也不是正式执行的必经步骤 | 校验同一次调用的 Bundle、业务输入和有效配置，返回验证结论与执行计划，不执行任务代码 |

**重设计采用 `run --dry-run` 承载消费端验证，不新增独立验证子命令。** 这是拟实现的需求，
不是现有 CLI 已支持的参数。它复用正式执行的参数解析、内容准备和输入校验，在启动任务
代码之前停止；正常 `run` 始终自行校验，不依赖事先预演或过去的验证结果。

```powershell
task-engine run --car .\bundle.car --input .\input.json --dry-run
task-engine run <bundle-cid> --gateway http://127.0.0.1:8080 --input .\input.json --dry-run
```

预演边界：

- 接受与正式执行相同的任务身份、输入和配置参数，检查互斥规则及有效值，返回本次目标、
  来源、预算与授权设置；不泄露秘密。预算只表示拟执行设置，不伪造任务已开始计时。
- 完整验证本地 CAR 的实际字节，或从选定 Gateway 获取并校验目标 Bundle 所需内容。
  不能把可解析 CID、成功连接来源或仅检查声明当作完整验证。
- 必须取得本次业务输入，校验 JSON、请求字段限制与 Bundle 输入 Schema；不因预演就
  允许省略业务输入或默认补 `{}`。只检查 Bundle 本身不代表一次执行预演完成。
- 检查无需执行任务代码即可确定的运行要求；不启动 Worker、不提交或调度真实 Task、
  不创建真实 Task/Run 执行记录、不执行任务代码或动态子调用。
- 可以读取文件、访问内容源并使用临时资源，因此不是零 I/O；结束前仍须确认自有资源
  清理，获取失败、中断和清理不确定不能报告预演成功，不写入执行历史冒充真实运行。
- JSON 明确区分验证与执行：建议成功返回 `dryRun: true`、`status: "validated"`、
  `exitCode: 0` 及必要的验证摘要和计划，不伪造业务结果、Task ID 或执行快照。
  验证失败沿用适用的非零错误分类；详细字段在接口设计时确定，不改写旧执行结果含义。

预演通过仅证明已检查的准备条件满足，不承诺未来内容源仍可用、正式准入和资源分配成功、
动态子任务可执行或业务运行成功，也不证明代码可信、安全或没有副作用。运行时预算、
动态授权和收尾等只能在正式执行中继续验证，预演不能通过试运行来预测任意代码的行为。

主任务行为契约：

- 单一 `task-engine` 入口，保留默认 JSON 输入输出；不新增 `task-engine-ai`。
- 保留现有稳定结果字段及可行动的退出码分类；stdout 不混入进度、错误或界面控制序列。
- 不以根 Task 终态、空队列或观察静默代替完整耗尽；不以进程退出伪造资源已回收。
- 取消与超时请求正常收尾；清理不确定必须明确失败，不报告成功。
- 可选 TUI 是同一主任务的交互层，不改变授权、调度、资源所有权和 JSON 业务语义。
- 本地 CAR 消费无需编译器或 Builder 依赖；不自动上传、pin、启动 Kubo 或切换公共来源。
- `--dry-run` 只预演准备与验证，不是另一种成功执行结果，不绕过正常执行时的重新校验。

## 3. 主任务的描述参数

下表描述拟议需求，而非现有功能清单。“有默认值”和“用户级配置”分别只标记是或否，
不描述输入渠道、发现规则或实现方式。认证及持久记录相关参数仅在相应候选能力纳入后适用；
用户级配置一列表示可供后续取舍的管理范围，不代表所有配置已获批准。

| 参数 | 描述 | 有默认值 | 用户级配置 |
| --- | --- | --- | --- |
| Bundle 身份/来源 | 本次要执行或验证的任务产物 | 否 | 否 |
| 执行或预演模式 | 正式执行还是只准备和验证 | 是 | 否 |
| CAR 预期根 CID | 对所选产物施加的额外身份约束 | 否 | 否 |
| 业务输入对象 | 满足任务输入契约的本次业务数据 | 否 | 否 |
| Gateway 列表 | 按 CID 获取任务内容时使用的服务 | 否 | 是 |
| 认证上下文 | 访问受保护内容源时所用的认证身份 | 否 | 是 |
| 执行者身份 | 本次执行所属的调用者身份 | 是 | 否 |
| 子任务授权 | 是否准许任务派生子调用 | 是 | 否 |
| 根 Task 时间预算 | 根任务允许的执行时间 | 是 | 是 |
| 整次执行预算 | 整次任务准备与运行的时间约束 | 否 | 是 |
| 子调用与运行资源预算 | 深度、并发、数量及运行成本的限制 | 是 | 否 |
| 内容获取与关闭预算 | 获取内容及回收内容访问资源的成本限制 | 是 | 否 |
| 输入与产物容量 | 允许接收的数据规模 | 是 | 否 |
| 执行记录策略 | 是否保存执行事实及保存的内容范围 | 是 | 是 |
| App data folder | 应用执行记录的存放位置 | 是 | 是 |
| 保留与隐私策略 | 执行记录的保留范围与隐私约束 | 是 | 是 |
| 结果交付方式 | 本次执行结论与业务结果的交付形式 | 是 | 否 |
| 交互呈现 | 面向自动化或人的交互方式 | 是 | 否 |
| 诊断与进度 | 执行过程的可观察性与详细程度 | 是 | 是 |
| 清理策略 | 本次执行拥有的资源如何收尾 | 是 | 否 |

无默认值不等于每次都要重复填写，用户级值也不等于可以改变已有任务语义。
整次执行预算的产品默认值仍待评估，当前模型不预设该值。
认证与持久记录是否纳入首版，分别在第 4、5 节说明。

## 4. 用户级参数：Config 与 Credential

| 参数 | 分类 | 敏感性与范围 | 存储与命令访问 | 管理需求 |
| --- | --- | --- | --- | --- |
| Gateway 列表 | Config，建议首批支持 | 通常非秘密，URL 仍须禁止夹带秘密；CID 模式适用 | 用户配置；查看有效值和来源，不包含认证秘密 | 设置、查询、重置来源 |
| 根任务与整次执行预算 | Config 候选 | 非秘密，影响运行边界 | 用户配置，严格校验；本次覆盖优先 | 设置、查询、重置常用预算 |
| 记录开关、data folder、保留策略 | Config 条件候选 | 路径和策略不是认证秘密，但可涉及隐私 | 仅在历史需求采纳后提供；配置变更不能隐式迁移或删除旧记录 | 设置、查询、重置；提示生效范围 |
| 诊断详细度 | Config 候选 | 选项非秘密，日志内容可能敏感 | 只控制细节，不关闭错误或污染 stdout | 设置、查询、重置 |
| 受保护 Gateway credential | Credential 条件候选 | 认证秘密，绑定明确 origin/账号，不向其他来源发送 | 保护存储或外部凭证提供者；与普通 Config 命令隔离 | 依认证机制设置/登录、查状态、替换、移除 |

**现状没有 Credential 支持；不得为了分类完整而新增认证功能。** 若纳入受保护 Gateway，
不接受把 token 写进普通配置、命令参数、错误日志或 URL；普通查询只显示安全状态和目标。
非交互注入应有清晰渠道，本地移除与远端撤销必须区分。构建端和消费端不能因同属一个
仓库就共享任意 credential。

用户级管理辅助任务的参数与默认：

| 辅助任务 | 参数与默认 | 完成与失败规则 |
| --- | --- | --- |
| 查询配置 | key 可选，默认全部受支持项；执行上下文可指定 | 显示有效值及来源，明确模式适用性，不触发执行 |
| 设置配置 | key 与值必填 | 校验来源、有限预算、路径与策略；不把授权开关永久化 |
| 重置配置 | key 必填，不默认全部清空 | 只删除 CLI 自有覆盖，不修改环境或 Kubo；说明下一生效来源 |
| 管理 credential（条件任务） | 目标在无歧义时可由选定服务确定，否则必填；秘密无产品默认值 | 凭证经安全渠道提供；状态不泄密，不猜账号或发送范围 |

Node 是否安装、Bundle 是否有效、Input 是否满足 Schema 都不是用户级 Config。
执行仍应检查环境与输入并给出恢复指引，但不能据此创造配置项。

## 5. 主任务产生的 CLI App 资源及查询、管理需求

| 资源 | 所有权与生命周期 | 查询需求 | 管理需求 |
| --- | --- | --- | --- |
| 本次 Task、Run、拒绝与错误事实 | CLI 本次 MemoryStore 域拥有，现状进程内保留，最终交付快照 | 执行中观察、终结后输出；不伪造跨调用可查 | 域封闭、耗尽与回收；现状无历史命令 |
| 预演验证摘要与执行计划 | 拟新增的本次调用交付结果，不是真实 Task/Run 记录 | 从 JSON 取回，明确只完成验证 | 不写入执行历史冒充运行，不新增预演资产数据库 |
| Worker、自有 Gateway client、临时 CAR 数据和句柄 | CLI 操作拥有，短期资源 | TUI/诊断可展示收尾状态，无须暴露内部控制接口 | 自动关闭；清理无法确认报告独立失败 |
| Bundle、共享内容节点与 pin | 用户或内容系统拥有 | 仅为本次执行读取与验证 | 不隐式上传、删除 pin 或关闭共享节点 |
| 业务结果与显式重定向文件 | 交付用户或调用方所有 | 默认 JSON 中取回 | 不当作 App history 自动清理 |
| 任务代码造成的外部副作用 | 任务与外部目标系统的责任，不自动归 CLI | CLI 可报告事实，但不保证完整审计或回滚 | 删除记录不撤销业务副作用 |
| 跨调用执行记录（候选） | 只有采纳持久记录需求后才成为 App 资产 | 按 ID 查询、最近记录列表、筛选、导出 | 有界保留、删除记录；不等于恢复执行 |

**待定的产品决策：执行者是否需要由 CLI 自己保存跨调用记录。** 当前没有，不等于永远
不需要；存在 Task/Run 数据，也不等于自动批准引入 history。应确认调用方保存 JSON
是否足够，以及用户是否真正需要退出后查询。data folder 已作为主任务参数被发现，
但只有采纳持久化后才需要生效，不能以“路径可配置”反推必须有数据库。

如采纳记录，辅助任务参数应至少这样建模：

| 辅助任务 | 参数与默认 | 完成与失败规则 |
| --- | --- | --- |
| 列表与筛选 | 默认最近一页；有限条数，时间、状态等筛选可选；目录来自有效配置 | 只查询记录，不重新执行任务 |
| 查看/导出 | 记录 ID 必填，不默选上一次；查询输出默认 JSON，导出目标需明确 | 不存在则明确报告；敏感字段遵循保存及访问策略 |
| 删除记录 | 记录 ID 必填，不能默认全删；目录来自配置 | 只删所选 App 记录，批量删除需额外范围与确认，不删用户输出或外部资源 |

采纳前还需明确：保存输入/结果的隐私默认、保存失败如何反映在结果中、记录和业务结果的
区分、并发写入与中断记录边界、目录变更后旧记录如何访问。不得为了记录失败掩盖已发生的
任务副作用，或把部分执行快照称为可恢复状态。

本报告不授权发布或改变现有 JSON 默认。后续实施需覆盖旧调用迁移、信号、退出码、完整
耗尽与清理行为；`run --dry-run` 复用无编译器的 CAR 校验器与执行准备逻辑，
而不把 Builder 引入 Engine，也不通过启动 Worker 来实现预演。
