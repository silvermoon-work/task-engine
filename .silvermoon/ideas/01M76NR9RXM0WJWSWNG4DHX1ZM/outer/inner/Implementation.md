# Implementation

## Steps

### I-S01: 验证模块加载兼容性

验证项目最低 Node 版本及支持版本的模块 hook、CJS 和 Worker 启动行为，确定不降低现有兼容性的入口方案；任何提高最低运行时版本的需要必须先明确提出。

### I-S02: 接入受控 IPFS 模块加载

在 Worker 范围接入模块加载适配，复用现有 IPFS 校验、读取、容量和取消机制，保持已验证 bundle 的授权边界。

### I-S03: 补齐回归验证与使用说明

覆盖入口加载、拒绝路径及生命周期行为，更新直接相关文档，不扩展 bundle 交付格式。

## Acceptance criteria

### I-AC01: IPFS 入口保持任务行为

集成测试证明现有 CJS bundle 可由 IPFS 模块入口运行，任务输入、结果、消息、日志和退出行为不退化。

### I-AC02: 读取与授权失败可观察

针对无效 CID、路径越界、未授权跨 CID、缺失内容、校验失败、容量超限与取消的测试证明明确失败，且无静默 eval 或临时文件回退。

### I-AC03: 运行时及隔离边界成立

以支持版本兼容性验证及回归测试证明 hook 在入口加载前生效、不修改宿主加载器，关闭和并发执行不串用权限。
