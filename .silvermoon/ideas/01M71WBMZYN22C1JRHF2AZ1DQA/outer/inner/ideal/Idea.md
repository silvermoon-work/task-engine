# Task Engine CLI：可信执行与本地引擎管理

## 问题

现有 Engine CLI 尚不能完整承载已批准的任务使用方场景，服务生命周期、
持久任务记录与内容缓存的管理也未形成一致的可验证闭环。

## 结果

按 2026-11-10 19:37 已批准的
[需求模型](./task-engine-cli-requirements.md)与
[CLI Spec v1.0](./task-engine-cli-spec.html)，交付可安装、可自动化的 Task Engine CLI。
两份同世界规范副本及其[基线说明](./baseline.md)共同约束本构想版本，不另立接口契约。

## 边界

- 仅实现 Spec 的 12 个 Engine 叶命令；Builder 由独立构想推进，不纳入本次交付，
  不新增 dry-run、独立校验、TUI、凭证管理、服务自动启动或内容发布。
- 本地受管实例按实际数据目录全生命周期互斥；任务及子任务记录、结果和全部日志持久化，
  重启遗留未完整结束任务失败且不重跑；最终结果必须确认完整释放。
- 仅持久 CID 块缓存，无应用容量配额或内存内容缓存；可选 Gateway、磁盘耗尽失败退出、
  离线同锁清理和保留历史传递可达引用保护均按完整 Spec 执行。

## 验收标准

1. 12 个命令的输入、配置优先级及默认、stdout JSON、错误与退出码均符合上述规范，
   无格式切换或交互确认，帮助和迁移说明可核对。
2. 真实运行及失败测试证明异步落盘受理、Worker 起算、完整释放、重启失败、
   持久记录和缓存安全清理成立，不把状态或进程退出冒充释放证明。
3. 经独立阶段审查后，单包 canary 发布、本地安装及真实 smoke 有可复核证据；
   不批量发布、不自动发布依赖、不发布 stable，不移动 tag 或 force push。
