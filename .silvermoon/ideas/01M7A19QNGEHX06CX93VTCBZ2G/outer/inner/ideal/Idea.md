# 支持 Task 输入与结果中的类型化 CID 引用

## 问题

当前 Task 将 JSON result 与可写文件树 output 分开表达，输入及父子任务结果也缺少统一的内容引用语义。组合检查的问题与参考资源时，需要额外维护输出目录和跨任务资源关系。

## 结果

让 input/result 契约支持可识别的 CID 引用，作者侧引用与传输编码可往返转换；以只读资源访问及受控内容写入替代 Worker 的可写 output space。方向与未决细节见[讨论记录](Discussion.md)。

## 边界

- 不引入 Blob 结果类型；通用引用只定位 CID，不附加 path，也不强制把目标打入结果 DAG/CAR。
- 引用类型必须与普通业务 JSON 无歧义区分；Task 不解释文档语义。资源保留、缺失和访问规则须明确。
- 仅调整准备阶段方向；具体契约 API、编码及迁移尚待确认，不提交构想验收，不实施或发布。

## 验收标准

- 输入、结果及父子组合的内容引用可往返，普通字符串和同形对象不被误解为引用。
- Worker 无需可写 Space 即可引用已有内容或存入新内容；存储失败与弱引用的可用性边界可观察。
- 明确旧 output/Space 契约的迁移边界，分离引用、内容保留与可选完整打包。
