# Deployment

准备阶段初版。现实验证限本机隔离消费与源码 CI；本请求未授权 npm 发布、release tag、
远端制品上传或共享 Kubo 操作。若需要外部设备，先确认访问及操作范围。

## Steps

### D-S01: 在隔离消费者重建并消费

从已验收源码构建本地制品，在独立消费者、私有内容目录及 Engine 数据目录重建 Task 和
浏览器样例；只传最终 CAR，断开原输入树和依赖来源后离线消费。

### D-S02: 核实平台和身份边界

使用 Windows 与 Linux 的隔离环境或 CI 验证同一黄金输入的根 CID 与 CAR 摘要，
记录源码提交、工具版本和准确 CID；不把本地成功称为已发布版本验收。

## Acceptance criteria

### D-AC01: 独立离线消费成功

保留隔离消费者的命令、Task 调用及浏览器断言结果；最终 CAR 单独足以消费，
import 挂载 CID 与源一致，且未请求任何未配置来源。

### D-AC02: 平台证据和清理明确

Windows/Linux 证据分别给出根 CID 与完整 CAR SHA-256，解释一致性边界；
自有进程、临时文件及借用 Store 生命周期可核实，失败不冒充成功，无发布或共享 pin 副作用。
