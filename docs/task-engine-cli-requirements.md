## 1. 用户与边界

直接面向的业务角色是**任务使用方**，拥有“启动引擎”和“执行任务”两个主场景。启动与调用是该角色的不同职责，不拆成不同业务角色；即使由同一方承担，两套参数仍保持独立。

**Bundle
Task 作者方**是协作角色，负责定义任务逻辑、输入输出约定并提供任务包。源码编写与构建归编辑器、SDK 和 Builder，不纳入本 CLI。

人、AI Agent 和 CI 是交互环境，不因此成为不同业务角色。

执行任务要求引擎已可用，不自动启动引擎。连接失败须明确报告，不擅自另启或切换引擎。

本 CLI 的服务启动、状态查询和停止仅管理本机受管 Server，不通过 URL 远程关闭其他引擎；调用任务和查询任务记录可以连接明确指定的引擎。远程服务健康查询与本地生命周期状态不同，目前只记录为候选，不新增已确认场景。

## 2. 主场景清单

| 标识 | 场景     | 所属角色   | 触发与目标                                       | 完成标准                                                               |
| ---- | -------- | ---------- | ------------------------------------------------ | ---------------------------------------------------------------------- |
| S2   | 启动引擎 | 任务使用方 | 需要准备可接收任务的执行环境                     | 引擎按配置启动并就绪，使用方获得可连接的服务地址                       |
| S1   | 执行任务 | 任务使用方 | 已有任务包和业务输入，希望完成业务工作并取得结果 | 本次任务及其子任务结果明确，本次执行所属资源释放已确认，结果返回调用方 |

### 外部交接与非目标

- 作者方先提供任务包；执行后的业务结果由调用方消费。
- 使用方可以先启动引擎，也可以使用已有引擎，不要求每次执行都重新启动。
- 启动完成不要求先执行业务任务，启动操作完成也不意味着服务停止。
- 执行任务不会因本次任务完成而停止共享引擎。
- 失败、中断及清理不确定须如实报告，不能冒充成功。
- 不因已有校验能力而新增独立的 check 或 dry-run 场景。
- 停止、状态查询和数据清理属于后述辅助场景。

## 3. 各场景参数

全局默认指产品内置默认，不是机器级配置文件。用户级配置表示支持可复用的用户值，不表示用户已经配置。

值的优先级为：本次值 > 用户级配置 > 全局默认。

| 类别     | 全局默认 | 用户级配置 | 含义                                                   |
| -------- | -------- | ---------- | ------------------------------------------------------ |
| 任务特定 | N        | N          | 由本次操作提供，可来自已有任务描述；不等于必须手工输入 |
| 用户特定 | N        | Y          | 无产品默认；可复用用户配置，否则由本次操作提供         |
| 产品默认 | Y        | Y          | 产品提供默认，用户及本次操作均可覆盖                   |

### S2：启动引擎

| 参数              | 含义                                                                   | 全局默认 | 用户级配置 |
| ----------------- | ---------------------------------------------------------------------- | -------- | ---------- |
| 绑定 Host         | 服务监听地址，默认仅本机                                               | Y        | Y          |
| 服务端口          | 服务监听端口，产品提供默认选择                                         | Y        | Y          |
| 引擎资源预算      | 服务整体并发、容量、派生规模及任务包内存驻留等限制，产品提供有界默认   | Y        | Y          |
| IPFS 磁盘缓存预算 | 持久内容块缓存的独立磁盘容量预算，不与任务包内存驻留预算合并           | Y        | Y          |
| IPFS Gateway      | 引擎远程读取任务包的外部内容来源，不是引擎自身入口，无普遍适用的默认源 | N        | Y          |
| 引擎数据存储位置  | 执行状态、运行日志、持久 IPFS 内容缓存等应用数据的存放位置             | Y        | Y          |

引擎资源预算及 IPFS 磁盘缓存预算均属于服务配置，不由单个业务任务改写。磁盘缓存与内存驻留分别有界、分别配置，二者的具体默认数值均未批准。运行记录和缓存存储位置归引擎侧，不重复作为任务调用参数。

### S1：执行任务

| 参数         | 含义                                                       | 全局默认 | 用户级配置 |
| ------------ | ---------------------------------------------------------- | -------- | ---------- |
| 任务包       | 本次执行的任务内容；任务包及其内容身份不重复算两个业务参数 | N        | N          |
| 业务输入     | 本次任务要求的业务数据                                     | N        | N          |
| 引擎服务地址 | 连接哪个已启动引擎，默认本机服务地址                       | Y        | Y          |
| 执行时间预算 | 本次任务的执行时限，产品提供有限默认                       | Y        | Y          |

### 固定约束与范围

- 已提供的子任务能力均已授权，不增加额外的子任务授权策略参数。
- 结果固定返回调用方，不设结果交付目标参数。
- 服务监听地址与调用连接地址、引擎资源预算与任务执行时限，分别具有独立语义和作用域。
- 默认本机服务地址不代表自动启动引擎。
- 如实报告和资源释放确认是固定约束，不是可关闭的参数。
- 暂不确定具体默认数值、认证机制或存储技术。
- 当前没有确认跨信任边界提供服务的需求，不将调用访问策略列为必备配置；这不意味着任意对外开放都是安全的。

## 4. 各场景辅助资源

### S2：启动引擎

| 资源               | 归属与生命周期                                                                                | 管理需要                                                         |
| ------------------ | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 引擎服务实例       | CLI 在本机创建、任务使用方管理；启动后持续服务，不随单次任务完成停止                          | 查看本地状态和连接地址、明确停止                                 |
| 引擎应用数据       | 引擎产生、使用方控制，包括运行状态和日志等；停止服务不自动删除                                | 查询记录、显式清理                                               |
| 持久 IPFS 内容缓存 | 引擎应用资源，保存按 CID 标识的内容块，位于引擎数据目录范围内；默认启用、有界，随服务重启保留 | 自动淘汰可回收内容，保留活跃任务依赖的块；不因此新增缓存管理命令 |
| IPFS Gateway       | 外部所有；引擎按配置使用，不随引擎启停创建或销毁                                              | 不纳入本 CLI 的生命周期管理                                      |

缓存命中时校验并复用内容块，缺块时通过配置的 IPFS
Gateway 获取；缓存不能替代任务包完整校验。该资源不是运行中的节点，不要求完整 IPFS
daemon，不自动上传、pin 或提供 IPFS 服务，也不承诺所有任务可离线执行。缓存的具体存储技术、淘汰算法及默认数值不在本次批准范围内。

### S1：执行任务

| 资源             | 归属与生命周期                               | 管理需要                                 |
| ---------------- | -------------------------------------------- | ---------------------------------------- |
| 任务包           | 作者、使用方或外部内容源所有；执行时只读使用 | 不修改、删除或自动发布原始任务包         |
| 本次执行工作资源 | 引擎为任务及子任务分配，执行终结后自动释放   | 正常情况下无需用户逐项管理               |
| 任务结果         | 属于调用方业务产出，执行后交回调用方         | 后续保存、消费由调用方决定               |
| 运行记录         | 复用引擎应用数据，按任务关联保存             | 查询任务列表及单次任务的状态、结果和日志 |
| 已运行引擎       | 本场景的共享依赖，不由执行场景创建或停止     | 复用引擎管理能力，不随任务结束停止       |

执行任务复用引擎的持久内容缓存；任务结束释放本次工作资源，不意味着清空缓存或停止引擎。多个任务可以共享同一内容块，内容块的可回收性不能仅以某条任务历史是否存在来判断。

### 共同边界

- 停止引擎若影响在途任务，必须明确说明影响，不能静默终止任务。
- 清理数据不能破坏仍在使用的数据或误删其他实例的数据。
- 清理任务历史不能顺便删除它用过的全部内容块；其他任务可能仍共享这些块。历史清理与缓存自动淘汰具有不同范围，活跃任务依赖的块不得淘汰。
- 日志不默认记录秘密或完整业务输入输出。
- 不额外建立调用端记录仓库或结果副本。

## 5. 按角色综合辅助场景

以下场景均属于任务使用方。按语义、作用域及所有权复用配置和资源，不仅凭名称相同而合并。

### 辅助场景清单

| 标识 | 场景             | 目标与完成标准                                                   | 服务于 |
| ---- | ---------------- | ---------------------------------------------------------------- | ------ |
| A1   | 管理用户配置     | 查看、设置、修改、重置可复用配置，能辨认有效值及作用范围         | S2、S1 |
| A2   | 查看本地服务状态 | 明确本机受管 Server 的状态及已知连接信息；证据不足不冒充已停止   | S2、S1 |
| A3   | 停止本地服务     | 明确在途任务受到的影响，确认所选本机受管 Server 停止且资源释放   | S2     |
| A4Q  | 查询任务列表     | 按条件找到任务，返回任务标识、状态和结果摘要；无匹配时明确说明   | S1     |
| A4D  | 查看任务详情     | 查看指定任务的状态、结果及关联日志；记录不存在或不可用时明确说明 | S1     |
| A5   | 清理引擎数据     | 仅清理明确选定的数据并报告结果，不破坏在用数据或其他实例         | S2、S1 |

### 辅助场景参数

| 场景 | 参数             | 含义                                                    | 全局默认 | 用户级配置 |
| ---- | ---------------- | ------------------------------------------------------- | -------- | ---------- |
| A1   | 管理动作         | 本次查看、设置、修改或重置                              | N        | N          |
| A1   | 配置项范围       | 本次涉及哪些配置                                        | N        | N          |
| A1   | 配置值           | 设置或修改时写入的值                                    | N        | N          |
| A2   | 本地实例选择     | 通过引擎数据存储位置选择本机受管 Server，不使用远程 URL | Y        | Y          |
| A3   | 本地实例选择     | 通过引擎数据存储位置选择要停止的本机受管 Server         | Y        | Y          |
| A4Q  | 引擎服务地址     | 向哪个引擎查询任务列表                                  | Y        | Y          |
| A4Q  | 查询条件         | 本次查询的筛选条件；不输入表示空筛选条件                | N        | N          |
| A4D  | 引擎服务地址     | 向哪个引擎查询任务详情                                  | Y        | Y          |
| A4D  | 任务标识         | 查询哪次任务                                            | N        | N          |
| A5   | 引擎数据存储位置 | 复用启动场景的数据位置配置                              | Y        | Y          |
| A5   | 清理范围         | 明确选择要删除的数据，不默认全删                        | N        | N          |

配置值是本次写入的内容，属于 N/N；保存后，它才成为其他场景可复用的用户配置。

查询始终具有本次筛选条件。省略输入表示空筛选条件，属于固定输入语义，而不是从全局或用户配置补入默认条件，也不自动套用已保存的筛选条件。

### 共享配置及资源

- A1 管理 S2、S1 中支持用户级配置的值，包括独立的 IPFS 磁盘缓存预算和任务包内存驻留预算。服务级配置与调用级配置保持独立，不混淆服务监听与调用连接、服务预算与任务时限。
- A1 新增用户级配置记录，保留至用户修改或重置，不混入凭证。
- A2、A3 复用本地引擎服务实例及其配套生命周期记录，通过同一数据位置选择目标；必须核实本机实例身份，不以端口、可复用 PID 或残留文件单独作为归属证明。状态查询不改变生命周期；停止操作必须明确实际对象及在途任务影响，并确认停止和释放结果。
- A4Q、A4D 只读访问同一份引擎记录，不新增存储。
- A5 复用引擎应用数据的位置与所有权边界，仅清理所选数据；清理任务历史不连带清空内容缓存，不按某个任务的历史关联直接删除其全部内容块。不因此增加一组缓存管理场景或命令。
- 暂无已确认的认证需求，不新增 Credential 管理。跨信任边界服务的身份认证与数据隔离需求尚未建模。
