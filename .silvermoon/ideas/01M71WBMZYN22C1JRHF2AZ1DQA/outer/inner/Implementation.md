# Implementation

准备阶段的轻量初版，构想验收后再细化；不表示实现已开始或候选功能已获批准。

## Steps

### I-S01: 确认命令契约与兼容范围

依据两份需求分析明确阶段、最小输入、构建目标和用户级值；逐项决定候选范围，
记录现有 car/check、JSON 与模板脚本的兼容路径，不提前扩张历史或认证能力。

### I-S02: 实现共享执行与交互契约

在既有包边界内调整两个 CLI，复用现有构建、CAR 校验与执行内核；
将消费验证接入 `run --dry-run` 的准备阶段，不启动任务代码或生成真实执行记录。
同步相关模板、帮助和文档，不把编译器引入消费端，不绕过授权或清理保证。

### I-S03: 验证主路径与失败行为

按选定范围验证默认值、用户级覆盖、产物、机器输出和可选交互，
覆盖既有调用、异常输入、中断、失败回收与所涉及的安全约束。

## Acceptance criteria

### I-AC01: 需求到接口可追溯

通过命令说明与测试证明每个命令对应角色任务，每个必填项不能安全默认，
Config、Credential 与资产功能均有已确认范围和明确的访问边界。

### I-AC02: 生产与消费契约一致

通过真实构建及消费测试证明所选最终产物可完整校验，消费端不依赖编译器，
预演与执行采用相同输入和配置校验，但预演不启动 Worker、调度 Task 或产生业务结果；
现有入口与模板脚本按已记录迁移策略工作。

### I-AC03: 自动化与生命周期不退化

通过针对性测试和仓库既有检查证明 JSON、退出码、信号、耗尽与清理契约有效；
可选交互不得污染机器结果，未确认功能不以成功占位返回。
