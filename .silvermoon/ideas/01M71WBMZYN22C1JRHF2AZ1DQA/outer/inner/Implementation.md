# Implementation

准备阶段的轻量初版，构想验收后再细化；尚未实施。
产品范围仅由 [Idea](./ideal/Idea.md) 绑定的已批准规范确定。

## Steps

### I-S01: 落实 Engine 命令与配置契约

对齐 12 个叶命令、帮助、输入校验、独立用户配置和统一 JSON 输出；
记录旧 Engine 调用迁移，不修改并行 Builder 契约或引入消费端编译器。

### I-S02: 实现生命周期与持久数据闭环

在既有包边界内实现受管后台实例、实际目录独占、身份与释放核实、异步落盘受理、
Worker 执行预算、重启失败、任务/结果/全部日志持久化，以及无配额持久块缓存和离线引用清理；
内部技术选型在实施阶段细化，不重新扩张产品接口。

### I-S03: 验证完整规范与失败边界

补齐规范到测试的映射，覆盖真实执行、中断、释放不确定、重启、目录别名互斥、
共享块传递引用、未知引用拒删、部分失败和磁盘耗尽；同步文档并运行 pnpm check。

## Acceptance criteria

### I-AC01: 命令与配置符合规范

通过自动化命令测试、帮助和迁移文档核对 12 个叶命令、CID/CAR 与单对象输入、
独立配置位置及优先级、默认值、错误字段、stdout/stderr 和退出码；不存在 dry-run 或交互确认。

### I-AC02: 执行与持久生命周期可信

通过集成与故障测试证明后台就绪、实际目录互斥、实例身份、受理先落盘不等拉包、
Worker 起算、同步取消与 await 中断差异、完整释放、重启失败不重跑及记录/结果/全部日志持久保留。

### I-AC03: 缓存清理与仓库检查通过

通过持久缓存与离线清理测试证明无 Gateway 不联网、无应用配额或内存内容缓存、
磁盘耗尽致命退出、同锁维护、保留引用传递可达保护、未知引用拒删及部分失败计数；
pnpm check 和 Silvermoon 检查成功，证据可供精确 implementationRevision 审查。
