# Task 输入与结果的类型化内容引用

## 问题

当前 Task 将 JSON result 与可写文件树 output 分开表达，输入及父子任务结果也缺少统一的内容引用语义。组合检查的问题与参考资源时，需要额外维护输出目录和跨任务资源关系。

## 结果

让 parameters/message/result 统一交换自带 cidPaths 的类型化 CID 引用载荷，作者侧引用与传输编码可往返转换；以受控 CID 内容访问替代 Worker 对外 Space 接口。已确认方向见[讨论记录](Discussion.md)，实施前条件见[待决定项](OpenQuestions.md)。

## 边界

- 不引入 Blob 结果类型；通用引用只定位 CID，不附加 path，也不强制把目标打入结果 DAG/CAR。
- 引用与普通业务 JSON 无歧义区分，按判别分支定位；本地新内容由运行临时持有、发布后由结果持有，外部弱引用不自动获得可用性承诺，Task 不解释文档语义。
- 首期支持 raw/UnixFS 文件与目录，以文件/目录 DU 提供流式内容及条目；直接替换当前内部协议并沿用现有 Schema/API V1，不重写历史制品。

## 验收标准

- 三个通道及父子组合的引用可往返，载荷可独立识别引用语义，普通字符串、同形对象及判别分支中的普通数据不误转换。
- Worker 无需 Space 即可按 CID 读取、按 CID 加 path 解析目标、成功存储并返回 CID；流式文件及目录访问、不支持内容和写入失败的边界可观察。
- 本地交付内容按运行/结果持有关系保持可用，直接替换旧交换协议且不升级 V1；只读树形便利包按需引入，不增大未使用它的 Task，不把保留等同于完整离线打包。
