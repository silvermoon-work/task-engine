## 1. 用户与边界

直接面向的业务角色是**任务使用方**，拥有“启动引擎”和“执行任务”两个主场景。启动与调用是该角色的不同职责，不拆成不同业务角色；即使由同一方承担，两套参数仍保持独立。

**Bundle
Task 作者方**是协作角色，负责定义任务逻辑、输入输出约定并提供任务包。源码编写与构建归编辑器、SDK 和 Builder，不纳入本 CLI。

人、AI Agent 和 CI 是交互环境，不因此成为不同业务角色。

执行任务要求引擎已可用，不自动启动引擎。连接失败须明确报告，不擅自另启或切换引擎。

本 CLI 的服务启动、状态查询和停止仅管理本机受管 Server，不通过 URL 远程关闭其他引擎；调用任务、任务信息、日志查询及取得最终结果可以连接明确指定的引擎。远程服务健康查询与本地生命周期状态不同，不在本轮范围，不新增场景或命令。

## 2. 主场景清单

| 标识 | 场景     | 所属角色   | 触发与目标                                       | 完成标准                                                               |
| ---- | -------- | ---------- | ------------------------------------------------ | ---------------------------------------------------------------------- |
| S2   | 启动引擎 | 任务使用方 | 需要准备可接收任务的执行环境                     | 引擎按配置启动并就绪，使用方获得可连接的服务地址                       |
| S1   | 执行任务 | 任务使用方 | 已有任务包和业务输入，希望完成业务工作并取得结果 | 本次任务及其子任务结果明确，本次执行所属资源释放已确认，结果返回调用方 |

### 外部交接与非目标

- 作者方先提供任务包；执行后的业务结果由调用方消费。
- 使用方可以先启动引擎，也可以使用已有引擎，不要求每次执行都重新启动。
- 启动完成不要求先执行业务任务，启动操作完成也不意味着服务停止。
- 执行任务不会因本次任务完成而停止共享引擎。
- 失败、中断及清理不确定须如实报告，不能冒充成功。
- 不因已有校验能力而新增独立的 check 或 dry-run 场景。
- 停止、状态查询和数据清理属于后述辅助场景。

## 3. 各场景参数

全局默认指产品内置默认，不是机器级配置文件。用户级配置表示支持可复用的用户值，不表示用户已经配置。

值的优先级为：本次值 > 用户级配置 > 全局默认。

| 类别     | 全局默认 | 用户级配置 | 含义                                                   |
| -------- | -------- | ---------- | ------------------------------------------------------ |
| 任务特定 | N        | N          | 由本次操作提供，可来自已有任务描述；不等于必须手工输入 |
| 用户特定 | N        | Y          | 无产品默认；可复用用户配置，否则由本次操作提供         |
| 产品默认 | Y        | Y          | 产品提供默认，用户及本次操作均可覆盖                   |

### S2：启动引擎

| 参数             | 含义                                                                   | 全局默认 | 用户级配置 |
| ---------------- | ---------------------------------------------------------------------- | -------- | ---------- |
| 绑定 Host        | 服务监听地址，默认仅本机                                               | Y        | Y          |
| 服务端口         | 服务监听端口，产品提供默认选择                                         | Y        | Y          |
| 引擎资源预算     | 服务并发、准备数量、派生规模、任务包大小等限制，产品提供有界默认       | Y        | Y          |
| IPFS Gateway     | 可选的远程内容来源；没有产品默认 URL，未配置则只查本地缓存，不隐式联网 | N        | Y          |
| 引擎数据存储位置 | 状态、日志及持久内容缓存的位置，默认使用 Home 下的产品目录             | Y        | Y          |

引擎资源预算属于服务配置，不由单个业务任务改写。历史任务记录不按数量设上限；持久内容缓存不设应用层容量配额，因此不再列为可配置预算参数，也不通过“0 表示无限”保留原接口。当前不提供内存内容缓存。运行记录和缓存存储位置归引擎侧，不重复作为任务调用参数。

Gateway 的 N/Y 表示没有内置网络来源，不再表示启动时必填。未配置时仅查本地缓存是固定行为，不是另一个默认 Gateway。用户显式提供的本地任务包仍按既有入口校验；缺失且缓存也没有的内容不会通过默认站点、网络发现或其他回退来源补齐。

默认数据位置统一为当前用户 Home 下的
`.silvermoon.work/task-engine`，不区分 Windows 与其他平台的产品路径。可复用的用户目录配置及本次显式目录仍按既有优先级覆盖默认值；生命周期操作与数据清理共用同一目录选择规则。

### S1：执行任务

| 参数         | 含义                                                                 | 全局默认 | 用户级配置 |
| ------------ | -------------------------------------------------------------------- | -------- | ---------- |
| 任务包       | 本次执行的任务内容；任务包及其内容身份不重复算两个业务参数           | N        | N          |
| 业务输入     | 本次任务要求的业务数据                                               | N        | N          |
| 引擎服务地址 | 连接哪个已启动引擎，默认本机服务地址                                 | Y        | Y          |
| 执行时间预算 | 从任务 Worker 启动开始计时；拉包、准备和排队不计入，产品提供有限默认 | Y        | Y          |

### 固定约束与范围

- 已提供的子任务能力均已授权，不增加额外的子任务授权策略参数。
- 结果固定返回调用方，不设结果交付目标参数。
- 服务监听地址与调用连接地址、引擎资源预算与任务执行时限，分别具有独立语义和作用域。
- 默认本机服务地址不代表自动启动引擎。
- 如实报告和资源释放确认是固定约束，不是可关闭的参数。
- 业务执行成功不等于整个任务已完成释放。同步执行及后续获取最终结果必须等待任务及其子任务所属执行资源释放；不以查询到成功状态代替释放确认。
- 全部命令直接执行显式表达的操作并返回结果，不做交互确认或额外的确认授权。目录归属、互斥锁、在用状态及输入范围检查仍须执行，不因此允许误删或取消无关任务。
- 数据目录、普通默认值及保留的九项服务限制默认值已明确，具体值见 HTML；认证机制或存储技术未由这些数值选择确定。持久缓存容量不再有应用配额默认值。
- 当前没有确认跨信任边界提供服务的需求，不将调用访问策略列为必备配置；这不意味着任意对外开放都是安全的。

## 4. 各场景辅助资源

### S2：启动引擎

| 资源               | 归属与生命周期                                                                                  | 管理需要                                                           |
| ------------------ | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 引擎服务实例       | CLI 在本机创建、任务使用方管理；启动后持续服务，不随单次任务完成停止                            | 查看本地状态和连接地址、明确停止                                   |
| 引擎应用数据       | 引擎产生、使用方控制，包括运行状态和日志等；停止服务不自动删除                                  | 查询记录、显式清理                                                 |
| 持久 IPFS 内容缓存 | 引擎应用资源，保存按 CID 标识的内容块，位于引擎数据目录内；默认启用、无应用容量配额，随重启保留 | 显式选择缓存清理，保留历史引用可达及在用的块；复用已有数据清理场景 |
| IPFS Gateway       | 外部所有；引擎按配置使用，不随引擎启停创建或销毁                                                | 不纳入本 CLI 的生命周期管理                                        |

缓存命中时校验并复用内容块；仅在配置了 IPFS
Gateway 时才通过它获取缺块。未配置时只查本地缓存，缺块使任务准备失败，不阻止引擎启动，也不使用隐式网络来源。缓存不能替代任务包完整校验。该资源不是运行中的节点，不要求完整 IPFS
daemon，不自动上传、pin 或提供 IPFS 服务，也不承诺所有任务可离线执行。缓存清理按下述标记清除语义处理，具体存储技术不在本轮设计范围内。

当前只做持久内容缓存，内存内容缓存留待未来性能优化。不做内存缓存不意味着读取、校验或 Worker 执行不使用内存；不以删除缓存预算参数代替既有任务包和协议大小约束。

缓存没有应用配额，也不按大小、冷热或期限自动淘汰；清理内容块由显式选择的缓存清理触发。若实际磁盘可用空间不足而无法存储所需内容，Server 必须以失败状态退出，而不是仅拒绝该任务后继续服务。不自动删除历史或活跃块来掩盖空间不足，也不启用隐藏内存缓存。此故障会影响在途任务，应停止接收新任务并处理所属任务及执行资源；不能保证已经释放时须明确报告，不能将退出当作释放证据。无法落盘的故障状态须明确说明，之后启动按既有规则处理遗留未完成记录，不自动重跑任务。

缓存容量增长与任务记录、日志、缓存索引等共用实际磁盘空间；“不设限”不保证物理空间无限，也不预分配磁盘。单个任务包大小、协议载荷和执行资源等既有约束不因此取消。

### S1：执行任务

| 资源             | 归属与生命周期                                               | 管理需要                                             |
| ---------------- | ------------------------------------------------------------ | ---------------------------------------------------- |
| 任务包           | 作者、使用方或外部内容源所有；执行时只读使用                 | 不修改、删除或自动发布原始任务包                     |
| 本次执行工作资源 | 引擎为任务及子任务分配，执行终结后自动释放                   | 正常情况下无需用户逐项管理                           |
| 任务结果         | 属于调用方业务产出，执行后交回调用方                         | 后续保存、消费由调用方决定                           |
| 运行记录         | 引擎侧持久保存任务记录与全部任务日志，不自动按条数或期限淘汰 | 查询任务信息与结果；日志独立分页查询，显式清理可删除 |
| 已运行引擎       | 本场景的共享依赖，不由执行场景创建或停止                     | 复用引擎管理能力，不随任务结束停止                   |

执行任务复用引擎的持久内容缓存；任务结束释放本次工作资源，不意味着清空缓存或停止引擎。多个任务可以共享同一内容块，内容块的可回收性不能仅以某条任务历史是否存在来判断。

任务持久化包括后续取得最终结果所需的已知执行结论、业务结果及释放确认依据；不因历史条数达到阈值自动淘汰记录或拒绝新任务。全部任务日志持久保存，不自动按容量、时间或日志级别截断已产生的日志；分页只限制单次读取，不是保留上限。显式清理可删除所选历史任务及其关联日志，磁盘不足或持久化失败须如实报告。不设历史上限不等于磁盘无限，也不允许静默丢弃日志。

### 共同边界

- 停止引擎若影响在途任务，必须明确说明影响，不能静默终止任务。
- 显式停止服务时，默认有在途任务就拒绝停止；调用方明确选择“取消在途任务并停止”时执行该动作，且仍须确认资源释放。缓存写入时实际磁盘空间不足引起的 Server 致命退出不属于该用户停止操作，不要求等待额外取消选项才能退出。
- 清理数据不能破坏仍在使用的数据或误删其他实例的数据。
- 清理任务历史不能顺便删除它用过的全部内容块；其他历史可能仍共享这些块。只有显式选择缓存清理时才对未引用内容执行标记清除，保留历史引用可达及活跃任务依赖的块。
- 日志不默认记录秘密或完整业务输入输出。
- 不额外建立调用端记录仓库或结果副本。

各设备上的引擎在重启后再次启动时，处理其本地数据目录中前一次运行已持久化但未完整结束的任务记录：统一标记为失败，记录因重启中断的原因并持久保存，不重新启动 Worker、不重新排队、不自动重提或续跑这些任务。适用于任务及其子任务；已经完整结束并确认释放的历史任务保持原结果和标识，不因重启改写。

“未完整结束”包括已受理但尚未开始执行的任务、准备或排队中的任务、运行中的任务，以及业务已结束但整个任务仍未完成释放的记录。任务失败标记不证明执行资源已经释放，仍须核实旧运行身份及归属资源，不能直接伪造释放完成。

重启处置由每台设备本地引擎完成，不新增跨设备扫描或控制能力；断电期间不可能实时写回，失败状态在下次启动时落盘。持久化记录是保留结果和失败原因，不是自动恢复执行。
