## 实施设计

CLI 以实际数据目录和持续持有的 SQLite 独占事务锁管理本机后台实例，
另以运行随机身份、HMAC 随机挑战控制通道及操作系统进程出生证据核实归属；
不靠 PID 或端口判定停止，也不向监听端发送实例密钥。
用户配置独立存储，不沿用旧 Kubo 环境发现或一次性嵌入执行命令。

受管 Server 复用现有 Task Engine、Worker 和 Bundle 校验，每个根执行使用独立执行域；
统一持久仓库记录受理、全部子任务事实、日志和完整释放证据，不恢复旧执行域。
业务 JSON 与内部请求信封独立，Worker 创建时才开始执行预算，包含握手启动；
元信息入口在加载 SQLite 宿主之前返回。
内容访问复用既有 CID 校验与 Gateway，但只在磁盘保存可复用块；
离线清理先完成显式历史范围，再完整标记保留引用图，之后才删除孤立块。

具体故障与子进程证据在主体世界支持文件中维护；不改已接受 ideal 树或规范副本。
已串行整合上游 CAR 归属重构，复用现有 `openCarSource` 离线块源，
不恢复独立 CAR 包或引入生产端编译器。完整交付文件、代码快照、
Spec→测试映射、检查结果和部署前置条件见 [实施验证](./verification.md)。

## Steps

### I-S01: 落实 Engine 命令与配置契约

对齐 12 个叶命令、帮助、输入校验、独立用户配置和统一 JSON 输出；
记录旧 Engine 调用迁移，不修改并行 Builder 契约或引入消费端编译器。

### I-S02: 实现生命周期与持久数据闭环

在既有包边界内实现受管后台实例、实际目录独占、身份与释放核实、异步落盘受理、
Worker 执行预算、重启失败、任务/结果/全部日志持久化，以及无配额持久块缓存和离线引用清理；
内部技术选型在实施阶段细化，不重新扩张产品接口。

### I-S03: 验证完整规范与失败边界

补齐规范到测试的映射，覆盖真实执行、中断、释放不确定、重启、目录别名互斥、
共享块传递引用、未知引用拒删、部分失败和磁盘耗尽；同步文档并运行 pnpm check。

## Acceptance criteria

### I-AC01: 命令与配置符合规范

通过自动化命令测试、帮助和迁移文档核对 12 个叶命令、CID/CAR 与单对象输入、
独立配置位置及优先级、默认值、错误字段、stdout/stderr 和退出码；不存在 dry-run 或交互确认。

### I-AC02: 执行与持久生命周期可信

通过集成与故障测试证明后台就绪、实际目录互斥、实例身份、受理先落盘不等拉包、
Worker 起算、同步取消与 await 中断差异、完整释放、重启失败不重跑及记录/结果/全部日志持久保留。

### I-AC03: 缓存清理与仓库检查通过

通过持久缓存与离线清理测试证明无 Gateway 不联网、无应用配额或内存内容缓存、
磁盘耗尽致命退出、同锁维护、保留引用传递可达保护、未知引用拒删及部分失败计数；
pnpm check 和 Silvermoon 检查成功，证据可供精确 implementationRevision 审查。
