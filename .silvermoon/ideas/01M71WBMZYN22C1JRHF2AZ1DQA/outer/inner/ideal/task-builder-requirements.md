# Task Builder CLI 需求分析报告

本文是 [CLI Redesign Idea](./Idea.md) 的理想世界支持文档，不代表功能已经实现。
现状基线为 `a635ed0`；“建议”是重设计方向，“待定”不构成已接受的功能范围。
分析采用用户角色、主任务、用户级参数管理、应用资产管理的方法，不从现有子命令反推需求。

## 1. 用户是谁？

主要用户是 Task 的生产者：编写任务代码与契约，并交付可供执行者消费的 Task Bundle。
人类开发者、AI 开发代理和构建流水线可以承担同一角色，不据此拆成不同 CLI。

Builder 负责项目脚手架、构建与产物交付；不负责执行任务、维护运行历史、启动内容服务，
也不默认承担依赖安装、上传、pin、认证或发布。用户项目与交付文件由用户所有，不因经
Builder 创建就变成 Builder App 的托管资产。

## 2. 主需求、主任务是什么？

**主需求：把用户编写的 Task 转换成可验证、可交付的执行包。**

主任务按 CLI 外部用户参与划分为两段，而不是按编译器流水线拆分：

| 阶段 | CLI 接收与交付 | 用户参与边界 |
| --- | --- | --- |
| 初始化 | 接收新项目位置，交付可编辑的任务项目 | 用户随后在编辑器中修改代码、契约与资源，必要时使用包管理器安装依赖 |
| 构建交付 | 接收已编辑项目与构建描述，交付所选目标产物和身份信息 | 构建内部自动完成编译、组装、必要编码与验证，不要求用户逐步驱动 |

已有项目可以直接进入第二段，不强制初始化。`init` 和 `build` 的独立调用有用户编辑这一
真实边界；编译、组装 Bundle 和编码 CAR 之间没有必然的外部参与边界。

**建议：将 CAR 建模为构建目标参数。** 默认最终交付 CAR，Bundle 目录作为可选的中间产物
目标；是否同时保留中间产物由输出策略表达。默认最终产物的建议需在命令设计阶段落实，
并为现有“build 目录，再 car”调用提供迁移路径，不能直接删除旧入口。

**构建成功必须意味着所选产物已通过必要的完整性验证。** 不应要求生产者再执行 `check`
才能确认构建结果有效。消费端验证收敛到 Engine 的 `run --dry-run`，同时验证 Bundle、
本次业务输入与执行配置，不新增独立验证任务。现有 Builder `check` 的兼容保留与弃用
路径另行设计，不能因归属调整而突然破坏调用方；它原先只接收产物，没有业务输入，
因此不能不加说明地直接等同于执行预演。

完成标准与行为约束：

- 初始化成功时文件完整、可供编辑；不合并或覆盖已有项目，不自动安装依赖。
- 构建成功时实际交付字节有效，身份与字节一致；选 CAR 时包含 CAR 完整性，不以仅验证
  内存中的声明结构替代最终产物验证。
- 失败或中断不报成功；只回收本次拥有的临时输出，不删除用户既有文件或源码。
- JSON 结果仍为默认机器契约。产物类型与结果呈现格式是两个不同参数，不复用同一语义。

## 3. 主任务的描述参数

下表描述拟议需求，而非现有功能清单。“有默认值”和“用户级配置”是两个独立判断，
均只标记是或否；不规定输入渠道或具体实现。用户级配置为建议的管理范围，尚未表示实现
或接受了这些能力。项目的明确业务语义不应被全局偏好悄悄覆盖。

### 初始化阶段

| 参数 | 描述 | 有默认值 | 用户级配置 |
| --- | --- | --- | --- |
| 项目位置 | 新项目的创建位置 | 否 | 否 |
| 项目名称 | 项目的包身份 | 是 | 否 |
| 初始任务名称 | 项目初始任务的名称 | 是 | 否 |
| 模板类型 | 要生成的项目类型 | 是 | 否 |
| SDK 版本 | 新项目使用的任务开发依赖版本 | 是 | 是 |
| CLI 与 Builder 版本 | 新项目使用的构建工具版本 | 是 | 是 |
| 最低运行版本 | 新项目声明的最低运行环境版本 | 是 | 是 |
| 依赖安装策略 | 初始化是否同时安装依赖 | 是 | 否 |
| 覆盖策略 | 如何保护已经存在的项目内容 | 是 | 否 |
| 结果呈现 | 初始化结果的呈现形式 | 是 | 是 |

### 构建交付阶段

| 参数 | 描述 | 有默认值 | 用户级配置 |
| --- | --- | --- | --- |
| 项目根 | 本次构建的项目范围 | 是 | 否 |
| 构建描述位置 | 项目构建说明的位置 | 是 | 否 |
| 任务名、最低运行版本 | 产物的身份描述与运行兼容性 | 否 | 否 |
| 源码入口、契约 | 待构建代码及输入、结果、消息的约束 | 否 | 否 |
| 入口模式、导出与 SDK 绑定 | 任务代码的入口约定 | 是 | 否 |
| 资源与二进制规则 | 附加资源的选择与内容类型 | 是 | 否 |
| 产物目标 | 最终 CAR 或中间 Bundle | 是 | 是 |
| 输出位置 | 构建产物的交付位置 | 是 | 否 |
| 中间产物保留 | 是否保留最终交付前的中间产物 | 是 | 是 |
| CID 交付 | 是否额外交付独立的产物身份文件 | 是 | 否 |
| 代码契约执行授权 | 是否允许构建期间执行契约代码 | 是 | 否 |
| 容量与遍历预算 | 本次构建允许消耗的资源范围 | 是 | 否 |
| 覆盖与失败回收策略 | 保护已有内容并回收失败产物 | 是 | 否 |
| 结果呈现 | 构建结果的呈现形式，区别于产物类型 | 是 | 是 |

版本偏好、产物目标、中间产物保留与结果呈现是否全部纳入首版用户级管理，仍需取舍。
这些偏好不能改写项目已经明确指定的构建语义。当前不因参数发现而新增构建历史或缓存；
若以后确认相应需求，再补充 data folder 等参数。

## 4. 用户级参数：Config 与 Credential

现状 Builder 没有自己的用户级配置或 Credential 管理。以下仅是从上表发现的候选，
不能据此认定 Builder 必须有完整 Config 子系统。

| 参数 | 分类 | 敏感性与范围 | 存储与命令访问 | 管理需求 |
| --- | --- | --- | --- | --- |
| 初始化 SDK/CLI/Builder 版本、最低运行版本 | Config 候选 | 非秘密，仅影响新生成的项目默认值 | 若采纳，使用用户配置；查看时显示来源，不自动修改既有项目 | 设置、查询、重置初始化偏好 |
| 默认产物目标 | Config 候选 | 非秘密，影响未显式选目标的构建 | 若采纳，用户配置；项目和本次选择优先 | 设置、查询、重置交付偏好 |
| 中间产物保留 | Config 候选 | 非秘密，仅涉及本次构建的中间交付物 | 若采纳，用户配置；不删除用户既有文件 | 设置、查询、重置保留偏好 |
| 结果呈现偏好 | Config 候选 | 非秘密，不改变产物业务语义 | 若采纳，用户配置；保留显式机器模式 | 设置、查询、重置 |
| 包管理器或内容服务凭证 | 非本 CLI 管理项 | 可能敏感，但现有主任务不执行安装、上传或发布 | 归对应包管理器或外部系统；不读取、复制或展示其秘密 | 当前无 Builder 认证任务 |

**首版判断：没有已证明必需的 Credential 管理需求；Config 候选应按跨项目复用价值取舍，
允许最终不增加用户配置命令。** 不能把项目的 `task.build.yaml` 误称为用户全局配置。

若采纳 Config，其辅助任务仍需分析参数：

| 辅助任务 | 参数与默认 | 完成与失败规则 |
| --- | --- | --- |
| 查询有效配置 | 配置项可选，默认所有受支持项；上下文默认当前项目 | 显示有效值与来源；不执行编译或修改项目 |
| 设置用户偏好 | 配置项和值必须显式提供 | 校验允许范围；拒绝把授权或项目语义写成全局默认 |
| 重置用户偏好 | 配置项必填，不默认全部清空 | 只移除 Builder 拥有的覆盖值；回落来源可解释 |

## 5. 主任务产生的 CLI App 资源及查询、管理需求

| 资源 | 所有权与生命周期 | 查询需求 | 管理需求 |
| --- | --- | --- | --- |
| 初始化项目、源码与构建描述 | 交付后归用户项目所有 | 用户通过项目文件与编辑器查看 | 不建立 App 项目注册表，不因 App 清理删除项目 |
| Bundle 目录、CAR、CID 文件 | 用户交付物，不是 App 托管历史 | 构建结果返回位置、身份；消费端可独立验证 | 不据此增加全局产物库存或删除命令 |
| 构建中的内存、暂存块和本次临时输出 | App 短期拥有 | 失败时提供诊断，不要求用户查询内部对象 | 成功、失败、中断都释放；只回收操作拥有的资源 |
| 可选未来编译缓存或构建记录 | 当前不存在，未纳入首版范围 | 尚无已确认需求 | 若后续引入，另定 data folder、保留、查询与清理策略 |

**当前没有需要用户独立查询或管理的 Builder App 持久资产。**
构建日志交付和失败诊断是主任务行为，不自动推出历史数据库、缓存管理或 `clean` 命令。
将来若引入 App 数据，存放位置归第 4 节的用户级参数管理，内容的查询与清理归本节。

现有 `car`、`check` 仍是公开接口，职责重组需要单独的兼容方案；这份报告并不授权删除命令、
改变已发布默认值或发布新版本。
