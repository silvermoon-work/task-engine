# Implementation

## Steps

### I-S01: 验证模块加载兼容性

依据已确认的至少 Node 22.15 方向，验证同步 hook 与 CJS 入口组合并确定支持下限，检查完整 CJS API；保持现有产物与握手协议，不把重建要求变成新的版本识别机制。

### I-S02: 接入受控 IPFS 模块加载

使用随包分发的 Worker bootstrap 接入只读已验证入口映射的模块适配，不在 hook 中联网。同步调整 Builder 地址生成、受影响的 Node 声明和模板，保持现有产物协议、任务生命周期及单文件交付形态。

### I-S03: 补齐回归验证与使用说明

覆盖重建产物加载、非法模块拒绝、CJS 行为、地址语义和生命周期，更新 CI、重建与使用说明；不新增产物 schema 或外部仓库交付依赖。

## Acceptance criteria

### I-AC01: IPFS 入口保持任务行为

集成测试证明重建的 CJS bundle 可由 IPFS 入口运行，import.meta.url 正确，任务输入、结果、消息、日志和退出行为不退化；同一入口不重复求值且不同 Run 状态隔离。

### I-AC02: 读取与授权失败可观察

针对无效 CID、路径越界、非入口路径、跨 CID、内容校验失败、容量超限与取消的测试证明明确失败，且无静默 eval、源码改写或临时文件回退；重建产物仍通过现有 task.yaml 校验与 SDK 握手。

### I-AC03: 运行时及隔离边界成立

在确定的最低 Node 版本及支持版本验证 require.cache、require.resolve 与内置模块；回归测试证明 bootstrap 先于入口生效、宿主加载器未改变、关闭和并发执行不串用权限。直接受影响的声明、模板和 CI 与实际下限一致。
