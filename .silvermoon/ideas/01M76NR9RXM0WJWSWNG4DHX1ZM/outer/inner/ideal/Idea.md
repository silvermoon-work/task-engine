# 支持通过 IPFS 地址加载 Worker 模块

## 问题

当前引擎校验 bundle 后把 worker.cjs 作为源码字符串交给 Worker eval 执行，IPFS 地址尚不能作为运行时模块入口，模块身份与内容读取之间存在特殊路径。

## 结果

让引擎管理的 Worker 能以 ipfs:// 地址加载已授权、已验证的 bundle 模块，保留稳定的内容地址与现有任务行为。详细要求见 [需求说明](requirements.md)。

## 边界

- 首期保持单文件 CJS bundle 契约，不以此引入多文件交付、任意跨 CID 导入或依赖自动下载。
- 复用 IPFS 内容读取与校验能力；模块授权独立于资源读取授权，不修改宿主全局加载行为。
- 与 IPFS fetch 支持分别推进；本构想不包含 fetch API。

## 验收标准

- 现有 bundle 能通过 IPFS 模块入口完成任务，不依赖源码临时落盘。
- 无效、越界或未授权模块请求明确失败，取消和关闭不遗留读取工作。
- 在声明支持的 Node 版本上验证加载能力及现有任务生命周期兼容性。
