# 执行与门限分工

本文补充 [Idea.md](./Idea.md) 的执行授权边界，不改变功能契约，不表示任一门限已通过。

## 委托范围

用户明确要求由一个 subagent 完成实施与部署，主 Agent 负责阶段门限审批。部署定义为发布本 idea 所需的 RC 包，再在 scottwei@office-ubuntu 安装真实 RC 并完成 smoke test。

- 主 Agent 审阅准确候选修订和验证证据，决定接受或要求修正，并记录对应门限决定。此权限由本次用户委托，不是 Agent 自行推定人类已验收。
- subagent 完成设计细化、代码、测试、相关文档和阶段证据，按 Silvermoon 流程提交准确修订；不能代替主 Agent 自批门限，不能在实施门限通过前开始 RC 发布。
- 同一 subagent 在阶段审批后继续后续工作，避免分散实现和部署上下文。主 Agent 可通过同任务消息提出修正或解除已审阅门限。
- 用户此前对讨论点的同意不自动充当任意未来修订的验收；主 Agent 仅在候选已同步、准确 submit 生效且证据符合契约时批准。

## 实施门限

实施须覆盖全部 I-* 标准，尤其是原 CID 保真、无机器缓存的离线 CAR、imports 修改检测、静态闭包断源执行、共享配置与并发写入，以及固定子调用身份的恢复。运行 pnpm check；失败不可写成通过。

先通过不同 UnixFS 分块的文件及目录引入验证产物格式，再扩大实现。若实验证明需要改变已确认语义，先向主 Agent 报告，不能用有损重编码、隐式下载、子调用授权或懒加载降级绕过。

## 发布和部署门限

RC 发布授权仅覆盖本 idea 所需包及其必要依赖；按仓库发布机制逐包确定精确版本、依赖顺序、main 精确提交 CI 与不可变 tag。禁止 stable、本地真实发布、stored token 绕过、移动 tag、批量 workspace 发布或改动其他服务。

subagent 向主 Agent报告逐包发布计划，主 Agent审阅后确认执行。部署门限以 [Deployment.md](../../Deployment.md) 的真实 RC 安装和远端 smoke 证据为准，发布成功不等于部署成功。

## 阻塞处理

SSH、Trusted Publisher、CI 或 registry 不可用时，记录实际失败与恢复条件并向主 Agent 报告。不得用本地验证替代指定远端，不得关闭校验或使用凭据绕过；也不进入无限重试。
