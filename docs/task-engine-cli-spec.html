公共选项、配置与默认值

叶命令均接受 --json、--quiet、-h / --help。其他选项仅在章节声明时可用；未知选项退出 2，不忽略、不自动纠正。公共选项置于叶命令之后。--json 与 --quiet 可组合；quiet 不隐藏结果、警告或错误。

业务值优先级仅为显式选项 > 用户配置 > 产品默认。不新增环境变量或项目级配置层。用户配置位置提案：Windows 为 %LOCALAPPDATA%\TaskEngine\config.json；其他平台为用户主目录内 .task-engine/config.json。文件不存在表示未设置；损坏、读取失败或未知键明确报错，不静默回退。

持久 IPFS 内容缓存与双预算边界

本节需求已批准并补录；具体选项、配置键、类型约束和默认数值仍待接口确认。

  • 缓存按 CID 标识的内容块，不是运行中的节点，不要求完整 IPFS daemon。 默认启用、有界，属于引擎应用资源，位于所选引擎数据目录范围内， 随服务重启保留，不在调用端另建一份缓存。
  • 命中时校验并复用，缺块时通过配置的 IPFS Gateway 获取； 缓存不能替代任务包完整校验，不能将损坏或不完整内容当作有效任务包。
  • 磁盘缓存预算与任务包内存驻留预算分开，均为 Y/Y： 有产品默认，支持用户配置和本次启动覆盖，不是任务调用参数。 两者具体默认数值均未批准。
  • 自动淘汰可回收内容，不删除活跃任务依赖的块。 任务结束释放执行资源不等于清空持久缓存； server stop 保留缓存，重新启动可校验复用。
  • 清理任务历史不能顺便删除它用过的全部内容块，因为其他任务可能共享这些块； 历史清理不代替缓存自动淘汰，也不因此新增一组缓存管理命令。
  • 不自动上传、pin 或提供 IPFS 服务，不承诺所有任务可离线执行。 缓存本身不改变 Gateway 的启动必需性提案，也不引入离线模式保证。

待讨论映射：独立启动选项 --ipfs-cache-max-bytes <bytes> 与用户配置 server.ipfsCacheMaxBytes 仅是候选。 具体默认数值未定；尚未加入上方配置键清单、启动语法或配置输出示例， 待讨论确认后再同步这些接口表面。缓存需求批准不批准这组命名。 淘汰算法、目录内部结构和完整 IPFS daemon 均不由此指定。

本地 Server 的选择与身份

server start/status/stop 使用同一 --data-dir 和 server.dataDir 选择本地受管实例， 不读取 client.engine，不接受 --engine 或任何远程 URL 作为管理目标。 数据目录仅用于确定本地实例归属，不因目录路径可访问就允许管理其他机器。 start 将可辨认的本地生命周期元数据保存在所选目录；status/stop 必须核对当前本机实例身份，不能仅凭可复用 PID、端口、网络回应或残留文件认定目标。 不接管由其他工具启动的服务。元数据为服务资源的配套记录，不新增实例注册管理系统。

status 可明确返回 not-started、ready、stopping、stopped； 只有归属和存活证据足够时才能判定。目录不存在表示尚未启动，不创建目录； 无法确认时报告 unknown 并退出 3，不能把不可达当作停止。 stop 对尚未启动或已确认停止的实例可幂等返回 0，但必须区分“本次确认完成释放”和 “未执行停止、仅已知服务不在运行”；后者不得补造 reclaimed:true。 共享退出码 3 在这些命令中表示无法确认本地服务状态，而非远程连接失败。

stdout、stderr 与数据结构

默认 stdout 为简洁人类文本；非 TTY 禁用颜色、动画及表格装饰，不承诺默认文本适合脚本。NO_COLOR 禁用颜色。所有进度、警告、提示及错误只写 stderr；TTY 可显示进度，非 TTY 仅输出必要阶段信息。不提供 TUI、交互式业务输入向导、--plain 或 --verbose 草案接口。

--json 成功时 stdout 仅一个 JSON 对象并换行，格式为 {"ok":true,"data":…}，data 由章节规定。失败且无可信结果时 stdout 为空，stderr 仅一个 {"ok":false,"error":{"code":"…","message":"…","hint":"…"}} 对象并换行，不再混入进度；hint 为恢复建议。run 的已知业务失败和已确认超时仍输出带 ok:false 的结果对象，另在 stderr 输出上述诊断对象。JSON 中时间为 UTC RFC 3339，任务标识是不可拆解字符串。示例标识 task-001 仅为说明。

无结果、尚未完成、结果未留存不可混用 null：详情用 resultState 区分 available / pending / not-retained，仅 available 时有 result（业务结果本身可以为 null）。日志字段 logs 为数组，logsTruncated 明确是否因原有留存边界而不完整，不假装拥有完整历史。

退出码

提议的可操作退出分类
码 含义
0 命令目标完成；任务查询查到失败任务本身仍为查询成功
1 其他操作失败、存储错误或服务内部错误
2 输入、配置无效或缺失；需要确认但未确认；安全前置条件不满足
3 目标服务不可用或连接中断，无法确认操作结果；不得据此宣称服务停止
4 指定任务不存在
5 本次执行业务失败或被拒绝

7 无法确认归属资源的释放；优先于其他业务结果
130 用户中断；run 的取消与释放已确认时方使用，否则按不确定结果返回 3 或 7

帮助、确认、中断与安全

帮助优先于执行，退出 0，不连接服务、不写数据。必需参数缺失时 stderr 给出简短用法和示例，退出 2，不挂起等待输入。只有明确 --input - 才消费 stdin。读取 stdin 和确认提示不得同时争用；有业务 stdin 的 run 不弹出确认。

危险操作先显示解析后的目标、影响范围及数量。只有 stdin、stderr 均为 TTY 时才可提示，提示写 stderr；非交互或 --json 模式必须通过相应确认选项授权，否则在变更前退出 2。--yes 只同意已显示/已选定的操作，不跳过锁检查、范围检查或释放确认。取消提示退出 130，不修改数据。

普通只读操作 Ctrl+C 停止客户端并退出 130；不会停止引擎。状态变更操作若已开始，须报告已确认的状态或明确结果未知；不能因为客户端退出而假装服务端回滚。身份验证、凭证管理及跨不可信网络的管理 API 不在本模型中；非本机监听须明确警告仅面向可信环境。

任务记录契约

列表项为 {taskId,status,createdAt,resultSummary}：status 为 pending/running/succeeded/failed/timed_out/cancelled/rejected；摘要只描述可用性和结论，不默认复制业务输入输出。查询按 createdAt 升序、同时间按 taskId 升序；空筛选不会暗加状态或时间过滤。

为避免无界响应，列表及详情日志均提议用 --limit（1–1000，默认 100）及 --cursor 做纯展示分页；不支持用户级配置。这是交互层分页，不改变 N/N 查询条件分类。nextCursor 为字符串或 null，不宣称遍历的是事务快照；游标只用于相同服务、任务及筛选，不兼容游标退出 2。任务标识可由 run 的进度、结果及列表获得。

task-engine server stop

待确认 · A3

停止本 CLI 管理的本地 Server 并等待资源释放确认；不提供远程停止能力，默认不终止在途任务。 

task-engine server stop [--data-dir <path>] [--cancel-running] [--yes] [--json] [--quiet]

适用数据目录配置、输出、退出码及确认及本地实例身份。停止过程端口关闭或进程消失本身不是本次资源释放完成的证据。

参数

  • --data-dir：可省略本地目录路径，映射 server.dataDir。 不接受 --engine，不读取 client.engine，不通过 URL 关闭其他服务。
  • --cancel-running：布尔，默认 false，无用户配置；显式授权取消在途任务。未给且存在在途任务时拒绝停止，退出 2。
  • --yes：布尔，默认 false，无用户配置；跳过确认提示但不跳过影响说明和实例身份检查。

预期输出与行为

stdout
确认停止及取消任务数；JSON data 为 {state:"stopped",dataDir,instanceId,changed:true,cancelledTasks,reclaimed:true}。 尚未启动或已确认停止时返回 {state:"not-started"|"stopped",dataDir,changed:false}， 不补造本次取消数量或释放证据。
stderr
停止前显示本地目录、实例与在途任务数；--json 成功时此信息包含于 data 的 stopped 结果，执行前通过显式选项授权；失败按共享诊断。人类模式给出影响说明和确认。
退出码
0 本次停止及释放确认，或已明确无需停止；2 有在途任务且未授权、元数据无效或缺少必要确认；3 本地实例状态/身份未知；7 本次释放不确定；1 其他失败；130 仅适用于请求发送前取消。
资源与交互
保留应用数据及持久 IPFS 内容缓存；释放运行资源不表示删除缓存内容， 不影响外部内容源。TTY 确认精确实例；非 TTY 或 --json 要求 --yes（尚未启动或已确认停止的无变更操作不需确认）。 仅操作已核实归属的本机实例，不接管外部进程。 请求绑定已识别实例，目标实例变化须失败。请求发送后中断不能撤销已发生的停机，应报告已知状态或未知结果。

task-engine run

待确认 · S1

将任务提交给已启动的引擎，等待本次任务及其子任务结果与工作资源释放确认后返回。 

task-engine run (--cid <bundle-cid> | --car <file>)
  --input <file|-> [--engine <url>] [--timeout-ms <ms>] [--json] [--quiet]

适用配置、输出、退出码及中断。例外：业务失败仍输出可信任务结果；永不自动启动引擎。

参数

任务调用参数
名称 类型 / 输入 必需性 默认 / 用户配置 约束
--cid Bundle 根 CID 字符串 与 --car 恰选一项 无 / 无 不接受任务名称或源码目录
--car 本地普通 CAR 文件路径 与 --cid 恰选一项 无 / 无 由调用端读取并传递给引擎；不是远端文件路径，不接受 -
--input JSON 文件路径或 - 必需 无 / 无 完整 JSON 对象；空输入、多个对象、无效 JSON 明确失败
--engine URL 可省略 client.engine 连接失败不启动或切换引擎
--timeout-ms 正安全整数 可省略 task.timeoutMs 服务端确认创建根任务后起算；不覆盖服务容量，不是提前断连预算

预期输出与行为

stdout
显示任务结论与业务结果；JSON 为 {ok,data:{taskId,status,resultState,result?,reclaimed}}。ok 仅在成功且清理确认时为 true；reclaimed 为 false 表示不能确认释放，不得成功。
stderr
人类模式显示受理后的任务标识和执行阶段；--json 无混杂进度。失败或不确定时提供任务标识（已知时）和 task detail 恢复建议，不默认打印输入或秘密。
退出码
0 成功；2 无效输入；3 无法连接或结果未知；5 业务失败/拒绝；6 已确认执行超时；7 清理不确定；1 内部错误；130 取消及释放确认。
资源影响
原任务包只读，不发布或 pin；本地 CAR 的传递不新增内容发布场景。执行复用引擎侧持久内容缓存， 缓存不能替代任务包完整校验；本次工作资源释放不要求删除可复用内容块。 执行数据由引擎记录；不写调用端结果副本，不停止引擎。
交互
缺必需参数显示用法并退出 2。--input - 在非 TTY 读至 EOF；TTY 先说明输入 JSON 后结束输入，不静默等待。Ctrl+C 请求取消本次任务及相关工作，等待确认；通信丢失不盲目重提或宣称取消成功，不取消其他任务。

校验并保存单项用户值；设置与修改使用同一命令。

task-engine config set <key> <value> [--json] [--quiet]

适用配置类型与优先级、输出及交互。例外：本次写入的 value 不从配置补入。

参数

  • <key>：必需已知键。
  • <value>：必需的显式值。字符串直接解析为字符串，端口和各限制项只接受十进制整数； 不再接受 limits JSON 对象，不得用 JSON null 表示重置。
  • 二者均无默认、无用户配置。无 stdin。保存路径值前按调用工作目录解析为绝对路径，避免重用时含义漂移。

预期输出与行为

stdout
显示已保存值、配置文件位置及生效范围；JSON data 为 {key,value,changed,appliesTo}。服务键 appliesTo=next-engine-start，client.engine/task.timeoutMs 为 future-client-invocations。
stderr / 退出码
0 保存成功（同值 changed=false）；2 值、键或已有配置无效；1 写入失败。中断在持久变更前为 130；变更后须如实说明保存状态。
资源与交互
仅更新用户配置文件，保留其他键；不得以写入成功冒充服务已重配。不启动、不重启引擎、不创建数据目录。显式单键赋值无需提示，TTY/非 TTY 一致。

待确认 · A1

移除单项用户覆盖，恢复产品默认；没有产品默认的项回到未设置。

task-engine config reset <key> [--json] [--quiet]

适用配置、输出及交互。例外：仅单键、可重设配置的显式操作，无额外确认提示。

参数

<key>：必需已知键，无默认或用户配置；无 --all、无 stdin。

预期输出与行为

stdout
显示重置后有效值；JSON data 为 {key,changed,effectiveValue,source,appliesTo}；source 为 product 或 unset，appliesTo 与 set 一致。已无用户值时 changed=false，仍退出 0。
stderr / 退出码
0 重置完成；2 键/配置无效；1 写入失败；变更前中断为 130，变更后明确实际状态。
资源与交互
只移除选定键的用户值，保留其他配置和全部引擎数据，不重启已有服务。无参数显示用法退出 2；TTY/非 TTY 均不提示。
